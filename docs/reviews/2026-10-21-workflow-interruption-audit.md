## 中断点与修正

| 原有中断点 | 当前行为与边界 |

| 必要私有函数、测试或漏列文件自动视为越界 | 同步计划并核对必要性，不增加确认轮次。 |
| 无关异常、可选能力失败阻止整项交付 | 记录并隔离；有实际依赖的动作保留待办，其余已授权工作继续。 |
| CodeGraph busy/not-fresh 阻止普通任务 | 保留原缓存和 unverified，允许使用标明来源的直接源码、测试证据；显式图契约不降级。 |
| 普通任务缺独立执行能力即全程停止 | 可完成实施、自审并报告独立审查缺口；明确要求独立审查的任务、显式契约及 Wiki 正式发布保留门禁。 |
| 发布能力或 ready 状态被附加到读取、Viewer、诊断 | 按本次操作检查身份、能力、版本、路径及一致性；恢复诊断和根定位不要求发布就绪。 |
| ready=false 阻止已有个人 run 调用 finish 恢复 | 仅 finish 可转给后端处理已有 run 的恢复/重放；完整能力、事务、回执、锁及 CAS 校验继续有效，不能启动新更新。 |
| 主题已授权，仍逐页或因 hash/revision 刷新反复确认 | 在原主题、来源、版本与权限内重算技术绑定及受影响 Review；真实范围或语义冲突才集中提问。 |
| 技术故障或 repair 次数耗尽自动启动问答/Grill-me | 先定位故障、自主修复授权范围内问题；只有实际缺人的事实、决策或授权才询问，不盲目重试。 |
| 合法空 Claims 因旧 pageVersion 阻止维护 | 空集合可只读使用，原 sidecar 字节仍参与 revision/CAS；非空过期集合、孤立记录、非法结构和链接路径仍拒绝。新 pageVersion 仅在正式发布及 Claims finalization 后写回。 |
| 尚未接受计划的 run 因规则身份刷新锁死 | 原 begin 锁内，仅在计划、队列、任务、删除项及候选均未建立时刷新可信 Skill/兼容身份；来源确认、Wiki 版本、语言、模式和 Skill 选择完全不变。冻结后拒绝刷新。 |

正式 Wiki 的 README 现行维护说明已同步；历史命令和原流程保留为归档，不增加现行安装或逐页确认门槛。入口原有的 `status: candidate` 被当前格式校验拒绝，已在同一分配候选页内规范为 `stable`，没有扩大页面范围。

## 保留的合理保护

- 保护用户已有修改、敏感或拒绝来源、权限和准确来源版本；无法安全合并的并发修改只暂停受影响动作。
- 正式 Wiki 仍经过来源绑定、只写候选、独立 Review、精确回执、锁和 CAS，不能以自审替代独立发布审查。
- 发布与 Git commit/push 分别授权；不自动重启共享 Hub、强关其他进程、重建图索引或清理编译缓存。
- 未运行的验证保留 unverified，不把静态规则检查、旧连接或旧指纹当作当前运行证据。
