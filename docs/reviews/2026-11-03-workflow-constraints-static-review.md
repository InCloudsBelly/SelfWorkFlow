# 跨案例审查后的约束修订与静态验收

本轮将新增四个对话、31 个轮次的历史对照结论落实到现有规则。原三例用于形成假设；新增长对话是窗口抽样，两个 Wiki 对话按同一任务链看待。历史检验只支持适用边界，不证明模型行为、token 或耗时收益。

## 修改范围

- `WORKFLOW.md`：全局只管目标/验收限定投入与交付粒度、依赖/证据有效性、完成依据；保留授权/绑定与必要缺口。普通问答的既有 Light 路径不扩成工程流程。次数、字符数不替代验收或收益证据。
- `workflow/modules/review.md`：按用户当前复审范围和方式履行覆盖；相关输入、规则或运行环境变化使依赖结论失效，不能只看文件字节或修改行，也不按轮数判复审多余。
- `workflow/modules/codegraph-read.md`：已知重试预算绑定已核实的阻塞对象、原因和状态；跨主题也可能共享同一锁，不同阻塞不混用预算。主题/阶段/版本名变化本身不重置，必要观察沿原作业继续；独立会话缺少旧状态时不冒称计数已共享。
- `workflow/modules/delivery.md`：交付增强复用证据时，同样核对实际依赖的环境/消费者；不增加默认 Skill 调用。
- `skills/workflow-skill-maintenance/SKILL.md`：用结论来源以外的对照案例和反例核对限制；相关任务链不当独立样本，证据不足不升级为全局通则。区分静态结构、历史适用性和部署实测。

未增加运行时模块、路由、阶段、Reviewer 角色或普通任务的验证表单；不关闭显式访谈、正式复审或必要验收。

## 静态正例与反例

这是规则一致性的静态核对，未调用模型执行模拟任务；真实路由和发布消费者另由现有自动化检查验证。

| 用例 | 输入/反例 | 必须保留的结果 |
| --- | --- | --- |
| S1 | 用户只需两句总结，无修改或新风险 | 沿既有轻量路径直接答复，不自动启动实现、测试或独立审查 |
| S2 | 用户只需四列表格，但分类需要查源 | 内部完成必要查证，交付按所需粒度；不把内部统计明细强加给用户 |
| S3 | 文件字节未变，但实际运行版本或消费者变化 | 使依赖旧环境的结论失效；核对真实消费者，只补受影响验证，不探测未用服务 |
| S4 | 用户原先禁止改测试，现在必要支持工作需要适配测试 | 原授权不覆盖新增动作，先取得明确授权；不能借“复用授权”越界 |
| S5 | 两个主题被同一服务锁、同一原因和状态阻塞 | 共享该阻塞的重试预算，不按主题分别重复维护 |
| S6 | 版本名或阶段变化，但原锁仍被占用 | 预算不重置；必要进度观察继续，不能重复启动维护 |
| S7 | 两个互不相关的阻塞对象 | 分别判定，不将一个阻塞的预算耗尽扩成全局停工 |
| S8 | 输入、相关规则或环境改变，或用户明确要求正式复审 | 履行当前范围/方式，复用仍有效证据；不能用“少重审”漏审约定项 |
| S9 | 首轮已发现问题，但仍有约定输入类别/消费者未覆盖 | 继续完成覆盖，不因发现数、次数或 token 预算停工 |
| S10 | 区分必要验收未完成与仅缺收益测量 | 缺必要验收证据不得报完成；验收满足即可交付，缺收益数据只限制“实测收益”声明 |
| S11 | 独立会话无法取得旧阻塞/重试状态 | 不假定共享计数，不冒称跨会话预算已强制执行；核对可得作业状态并遵守实际锁保护，不为规则另建共享账本 |
