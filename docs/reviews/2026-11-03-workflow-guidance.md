## 与原规则相比的实际变化

原入口已经要求同版复用和定向投影。本轮补上三处决策机制：在投入前固定关键前提；以“还有哪个必要缺口”选择追加动作；按覆盖失效的原因缩小后续工作。审查记录在既有任务状态中组织，不引入额外账本。图谱原先按“换阶段”触发额外核对、以“根/阶段”划分重试预算，改为核对有效性与同一阻塞状态；新 MCP 查询在无可信 watcher 时仍核对，独立 CLI 不假定共享缓存，保持原 freshness 和发布保护。

## 静态适用性核对

- 输入、约束与已审范围均未变化：复用有效证据；收到再审请求仍响应，补充必要反例/缺口，避免从零重扫。
- 输入或关键前提变化：失效相应结论，并检查共享状态与消费者影响；不能把“复用”当成免审。
- 需要用户决定取舍或关键事实无法查明：先查现有上下文与工具，再合并会影响结论的缺口和选择；显式访谈仍按用户要求进行。
- 首轮发现问题但尚有未覆盖验收项：继续完成约定范围，不能用发现数量或预算结束审查。
- 外部维护被同一作业占用：观察原作业进度，遵守重试边界，不并发维护；能力缺口只阻依赖工作。

以上为规则与反例的静态核对，不代表真实模型触发率、实际 token 或耗时收益实测。本轮不重新读取三会话历史，也不重跑上一轮未受影响的测试。
