# 轻量知识沉淀交接设计

## 目标

SelfWorkflow 在完成 Review 和 Verify 后，仅当任务产生可复用的技术知识时主动提示一次是否沉淀；用户接受后，C7OpenWiki 同时获得 Agent 整理结果与支撑关键结论的原始源码、配置、测试或文档，使后端能够独立判断、去重和筛选。

## 设计

- 提示属于轻量 Agent policy，不新增状态机或新的 MCP 工具。可复用信号包括稳定架构关系、已验证排障结论、测试策略、项目规范和可重复操作；简单问答、机械修改、临时状态和未形成稳定结论的任务不提示。每个任务最多提示一次，用户拒绝后不再追问。
- 用户明确要求维护 Wiki 时直接进入现有知识流程，不重复询问是否沉淀。C7 不可用时不阻塞已验证的代码交付，只报告知识同步待办。
- 知识交接使用双层证据：`materials` 保存紧凑的处理后结论；`sourceManifestId` 绑定直接支撑或反驳关键结论的原始源码、配置、测试和原始文档。重要的处理后 Markdown 可以作为来源之一，但不得成为存在原始证据时的唯一来源。
- SelfWorkflow 的 C7 适配器必须把经过边界校验的 `materials` 与 source manifest 绑定字段原样传给 query/update；当前适配器缺少该转发，属于本次最小实现范围。C7OpenWiki 后端和 MCP Schema 不变。
- 外部 Agent 只选择最小充分的原始文件集合，不扫描或提交整个仓库。来源清单继续经过 C7 的 hash、敏感检查和用户确认；文件变化后确认失效。
- OpenWiki 把 Agent 结论视为组织线索，并与原始来源独立交叉判断；冲突时优先当前源码、配置和测试。正式 Wiki 只保存整理知识、来源标识/hash和必要短摘录，不复制整份原文。
- 最终写入仍必须展示摘要并获得用户明确“确认写入”；本设计不削弱现有 revision/CAS、复审和敏感信息护栏。

## 验收

1. 轻量核心同时定义一次性提示的正触发、误触发和拒绝后停止边界。
2. C7 Skill 明确要求处理后材料与关键原始来源组成双层证据包，并要求 OpenWiki 独立核验。
3. C7 适配器实际把合法 `materials` 与绑定的 source manifest 一起传给 query/update，并拒绝越界材料结构。
4. 现有 source manifest、写入确认、revision 和敏感信息规则保持不变。
5. 定向测试覆盖上述规则，knowledge profile 能构建并安装到全局运行时。
