# AmnisStudio 前端可视化与链接访问设计原稿

**状态：** 基于现有页面黑盒行为和前端资源的逆向设计稿

**日期：** 2026-10-10

**适用对象：** 后续基于当前页面改造个人版资产管理、项目管理或生产看板功能。

**目标：** 保留当前页面的视觉信息密度和操作习惯，同时把页面状态、链接访问、数据加载、图片产物和路由设计改造成可维护、可扩展、可脱离当前域名运行的前端系统。

---

## 1. 设计边界

这份文档只负责前端的可视化和访问层，不重新定义 Redmine、P4、工程目录和截图服务的内部实现。后端数据链路见：

[美术侧资产项目管理系统实施计划](../plans/2026-10-10-art-asset-project-management.md)

当前页面的实现可以分为三层：

```text
AppShell / View State
  ├─ 页面布局、导航、全局状态、弹窗、抽屉
  ├─ CalendarView
  ├─ ProductionProgressView
  ├─ RedmineWorkbenchView
  └─ AppearanceCatalogView
        ↓
Frontend API Client
        ↓
同源业务 API / 静态快照 fallback / 外部 Redmine 链接
```

必须区分以下三件事：

- “当前页面如何工作”是逆向观察结果，不代表应当原样复制。
- “个人版的接口和路由”应当由配置驱动，不能把当前域名、端口和项目名写死。
- “页面显示正常”不等于“链接、权限和数据新鲜度正确”；这三类状态要分别表达。

## 2. 当前前端的已观测实现

### 2.1 前端运行形态

已观察到当前域名返回静态 HTML 和打包资源，主要资源包括：

- React/Vinext 风格的运行时和页面 bundle。
- 页面脚本：`/assets/page-BZqANlq5.js`。
- 样式文件：`/assets/index-DsbrrMnV.css`。
- 页面标题为“时装投放管理台”。

当前页面没有观察到 `react-router`、`useLocation`、`useNavigate`、`pushState` 或 `replaceState`。四个主视图更接近“单 URL + React 内存状态切换”，而不是四个可以直接分享的 URL 路由。

这带来两个直接结果：

1. 刷新后通常回到默认视图，当前筛选条件不一定可以恢复。
2. 用户不能直接复制一个“某个资产详情、某个甘特筛选、某个目录搜索”的深链接。

个人版应保留单页体验，但使用真正的 URL 路由和 query 参数保存可分享状态。

### 2.2 API 基地址选择

当前 bundle 中的 API 基地址逻辑为：

```text
非 localhost 环境       → /api
localhost:3014          → http://127.0.0.1:8772/api
其他 localhost/回环地址 → http://127.0.0.1:8767/api
```

非本机访问依靠同源 `/api`，本机开发则根据端口切换到不同的本地自动化服务。这说明页面本身没有把 Redmine 数据直接放进浏览器，而是依赖一个后端/自动化 API。

当前编辑鉴权还会读取：

```text
sessionStorage key: fashion-calendar-edit-password
request header:     X-Fashion-Edit-Password
```

个人版不能继续使用“密码放入浏览器 sessionStorage + 自定义 header”作为生产认证方式。该机制只能作为当前页面的兼容事实记录；新系统应改为 SSO、HttpOnly session 或短期 token。

### 2.3 页面壳层

当前 CSS 使用一组固定的设计 token：

```css
--ink:    #171c2a;
--muted:  #6b7280;
--line:   #e5e8ef;
--panel:  #ffffff;
--canvas: #f3f5f9;
--accent: #6956e8;
```

整体结构为：

```text
页面背景 canvas
  └─ Topbar
      ├─ 品牌图标
      ├─ eyebrow + 页面标题
      └─ 数据来源/自动化状态胶囊
  └─ AutomationJob 状态条（任务运行时出现）
  └─ View Navigator / Control Deck
  └─ 当前功能面板
```

主要视觉特征：

- 页面背景使用浅灰渐变和局部紫色 radial gradient。
- 内容区最大宽度约 1920px，页面两侧保留 24px 间距。
- 顶部状态采用胶囊、圆点和颜色表达在线、连接中、离线、过期。
- 卡片使用白底、浅边框、圆角和低强度阴影。
- 主要动作使用紫色渐变，危险或过期状态使用红色/橙色。
- 长表格不压缩到卡片中，而是保留横向滚动和固定列。

个人版应该保留这些信息层级，但将颜色、品牌、标题、项目名和数据源名称放入主题配置。

## 3. 主视图的可视化设计

### 3.1 投放日历视图

#### 当前行为

日历视图是“业务表格 + 筛选控制 + 局部编辑/导入”的组合，而不是普通月历组件。其数据一般包含：

- 来源行、版本、月份、周次、日期。
- 每个日期下的投放单元格。
- 资产名称、类型、渠道、计划日期、负责人和 Redmine 单号。
- 男/女变体、配置状态、截图状态和实际投放信息。

页面还包含类似 Excel 的导入、导出、模板、刷新和校验动作。当前样式中有分组表头、固定列、导入预览表格和错误列表。

#### 个人版实现建议

```text
CalendarPage
  ├─ CalendarToolbar
  │   ├─ 时间范围
  │   ├─ 版本/周次/渠道筛选
  │   ├─ 搜索
  │   ├─ 导入/导出
  │   └─ 数据新鲜度
  ├─ CalendarGrid
  │   ├─ GroupHeader
  │   ├─ StickyHeader
  │   ├─ CalendarRow
  │   └─ CalendarCell
  └─ AssetDetailDrawer
```

表格单元格只显示摘要状态；完整配置、Redmine 任务、截图和来源血缘在右侧抽屉展示。这样可以避免一个单元格承载过多 JSON 字段。

#### 注意事项

- 日期统一按 `Asia/Shanghai` 解析和显示，后端传 ISO 8601，不能用浏览器本地时区猜测日期。
- 计划值、实际值、人工覆盖值要使用不同视觉标识，不能只覆盖成一个字符串。
- 导入必须先进入预览和错误校验，不要在浏览器选择文件后直接覆盖线上数据。
- 列宽和行高需要稳定；不要让长名称撑破整张表。
- 过滤状态要写入 URL query，便于复制链接和恢复现场。

### 3.2 制作进度视图

#### 当前行为

制作进度是一个宽表格，当前 CSS 具有以下明确特征：

- 表格最小宽度约 `2160px`。
- 名称列约 `176px`。
- 截图列约 `124px`。
- 投放/版本信息列约 `170px`。
- 标准列约 `116px`。
- 表头使用 sticky 定位，存在两层分组表头。
- 使用 `progress-virtual-spacer` 进行简单的行虚拟化/占位，避免一次渲染所有行。
- 行有完成、逾期、风险、选中等背景状态。
- 资产行包含缩略图、男女变体、阶段节点、Redmine 单号和编辑器命名。

页面交互包含：

- 按名称、版本、渠道、Redmine、编辑器命名搜索。
- 按资产类型、阶段、状态、周次筛选。
- 点击行打开资产详情。
- 查看和编辑截图/产出图。
- 查看评论和 Redmine 最新产出。

#### 个人版实现建议

```text
ProductionProgressPage
  ├─ ProgressToolbar
  ├─ ProgressSummaryCards
  ├─ VirtualizedProgressTable
  │   ├─ FrozenIdentityColumns
  │   ├─ StageColumns
  │   ├─ GenderMilestoneCell
  │   └─ ArtifactThumbCell
  ├─ AssetDetailDrawer
  ├─ OutputImageModal
  └─ CommentPanel
```

阶段列不要在前端写死成九列。后端返回 `stageDefinitions`，前端根据阶段定义绘制列，从而可以替换为个人的美术流程：原画、模型、绑定、材质、特效、审核、交付等。

#### 性能注意事项

- 行虚拟化必须以滚动容器的可视区域为依据，不能只用 CSS 隐藏行。
- 资产列表接口只返回缩略图 URL 和必要摘要，原图按需加载。
- 图片 `<img>` 使用 lazy loading，并在抽屉关闭时释放 object URL。
- 筛选、排序和阶段聚合尽可能由后端读模型完成，前端只做轻量交互。
- 不能把完整 `production-outputs.json` 或包含 base64 图片的几十 MB JSON 放到首屏请求中。

### 3.3 制作分析和 Redmine 甘特视图

#### 当前行为

当前页面没有使用 Recharts/ECharts 等通用图表库。甘特图是自定义 DOM/CSS 实现：

- 左侧任务信息区固定宽度约 `300px`。
- 右侧是可横向滚动的时间轴。
- 表头 sticky，月份层和日期刻度层分两层。
- 时间尺度支持周、月、季度、年。
- 任务条通过计算 `left` 和 `width` 进行绝对定位。
- 有今天线、任务条、未设置日期任务列表和图例。
- 任务条颜色区分进行中、待验收/完成、逾期、计划等状态。
- 搜索和专业/分组/负责人筛选在工具栏完成。
- 还存在成本计算子视图和 CSV 导出动作。

甘特条本身是外部链接：

```html
<a
  href="https://c7-game-redmine.corp.kuaishou.com/issues/{issueId}"
  target="_blank"
  rel="noreferrer"
>
```

#### 个人版实现建议

甘特图应拆为三个模块：

```text
GanttView
  ├─ GanttToolbar
  ├─ GanttHeader
  │   ├─ MonthLayer
  │   └─ TickLayer
  ├─ GanttTaskColumn（sticky left）
  ├─ GanttTrack
  │   └─ GanttBar
  └─ UndatedTaskList
```

时间计算接口固定为：

```typescript
type TimelineScale = "week" | "month" | "quarter" | "year";

type TimelineRange = {
  start: string;       // ISO date, Asia/Shanghai semantics
  end: string;
  dayWidth: number;
};

function dateToOffset(date: string, range: TimelineRange): number;
function durationToWidth(start: string, end: string, range: TimelineRange): number;
```

不要在 JSX 中直接混合日期计算、颜色判断和 DOM 定位。先把任务转换为 `GanttBarModel`，再渲染。

#### 甘特图注意事项

- 没有结束日期的任务不能随意绘制成一天，应进入“待确认”列表。
- 任务条最小宽度要有可点击区域，但 tooltip 中必须显示真实日期。
- 时间轴、今天线和任务条必须使用同一时区和同一日期截断规则。
- 大量任务需要按当前筛选结果和可视时间范围裁剪，不能将全部任务都绘制成复杂 DOM。
- 外部 Redmine 链接必须由 `LinkBuilder` 生成，不能让任务标题或用户输入拼接任意 URL。

### 3.4 外观查询/资产目录

#### 当前行为

外观查询是全高的白色卡片和表格：

- 顶部显示标题、匹配数量和数据更新时间。
- 支持关键字、来源、子类型、版本、登记状态筛选。
- 表格显示 FashionID、ItemID、资产名、外观名、性别、版本和登记状态。
- 男女外观可能被分组成一个套装/配对记录。
- 登记状态显示可登记、已登记、未登记、被阻塞及原因。
- 数据刷新提示当前是读取已保存的配置，不一定触发实时 P4/工程扫描。

#### 个人版实现建议

- 将“查询”和“登记”分离为两个权限动作。
- 默认只加载分页摘要，点击行后再加载完整资产关系和来源血缘。
- 对男女配对显示明确的双向关系和不一致告警。
- 筛选条件写入 URL：`/catalog?q=...&source=...&version=...`。
- 登记动作必须显示 fingerprint、当前版本和来源时间，防止登记过期数据。

### 3.5 图片预览、缩放和产出图编辑

当前页面存在通用图片预览和产出图编辑能力：

- 使用固定遮罩层、模糊背景和深色 modal card。
- 图片按容器最大尺寸 `contain` 显示。
- 支持滚轮缩放，缩放范围约为 1–5 倍。
- 放大后可以拖动查看局部。
- 产出图编辑区域使用 canvas 进行图片缩放/重采样。
- 图片可从接口 URL fetch 为 blob，再转换为浏览器预览数据。
- 当前页面会区分 Redmine 产出和前端独立登记的产出。

个人版需要注意：

- 预览用的 object URL 必须在 modal 关闭时 `URL.revokeObjectURL`。
- 原图、缩略图和编辑结果使用不同权限，不要用同一个公开路径。
- canvas 导出前固定最大像素和文件大小，避免浏览器内存暴涨。
- 旋转、裁剪、压缩属于用户操作，保存前显示原图和新图的差异。
- 图片加载失败时显示来源、时间和重试入口，而不是空白区域。

## 4. 链接访问设计

### 4.1 链接分类

| 链接类型 | 当前实现 | 个人版设计 |
|---|---|---|
| 页面主视图 | React 内存状态切换 | URL 路由 `/calendar`、`/progress`、`/analysis`、`/catalog` |
| 页面筛选 | 主要保存在组件状态/sessionStorage | query 参数，可复制、刷新恢复 |
| 资产详情 | 当前通过抽屉/弹窗打开 | `/assets/{assetId}` 或同页 drawer + URL 状态 |
| Redmine 任务 | 固定 host + `/issues/{id}`，新窗口打开 | 服务端下发项目链接配置，客户端只传合法 issue ID |
| 文本中的 URL | 自动识别并转为新窗口链接 | 只允许 `https` 和配置域名，统一 `noopener noreferrer` |
| 图片/产物 | API 返回路径或 URL，前端 fetch/blob/预览 | 返回 `artifact_id` 和短时 URL，不返回工程盘路径 |
| 本机恢复 | `fashion-calendar://recover?...` 自定义协议 | 个人版默认移除，除非明确需要本机客户端桥接 |

### 4.2 推荐的个人版路由

```text
/                         总览
/calendar                 投放/排期日历
/progress                 制作进度
/analysis                 制作分析/甘特
/catalog                  外观/资产目录
/assets/:assetId          资产详情
/tasks/:issueId           任务详情摘要或 Redmine 跳转页
/sync-runs                同步记录和数据新鲜度
```

筛选条件使用 query：

```text
/progress?week=2026-W41&stage=model&status=overdue&q=clown
/analysis?scale=month&group=character&assignee=...
/catalog?source=fashion&version=Y1S1.1&registration=unregistered
```

query 参数必须经过 schema 校验；未知参数忽略，非法值回退到默认值，不允许因为一个坏参数导致整页白屏。

### 4.3 LinkBuilder 接口

所有外部链接集中生成：

```typescript
type ExternalLinkConfig = {
  redmineIssueBaseUrl: string;
  allowedHosts: string[];
};

interface LinkBuilder {
  redmineIssue(issueId: number | string): string | null;
  artifact(artifactId: string): string;
  sourceFile(sourceId: string): string | null;
}
```

规则：

- `issueId` 必须匹配数字或后端分配的合法 ID，不能直接接受完整 URL。
- `redmineIssueBaseUrl` 来自配置或后端元数据，不能写死 C7 项目域名。
- 外部链接使用 `target="_blank"` 和 `rel="noopener noreferrer"`。
- 不允许将 Redmine cookie、SSO ticket、编辑密码或内部文件路径编码进 URL。
- 用户可见的链接失败要有 fallback：复制 ID、显示来源或重试，而不是静默无反应。

### 4.4 API 客户端和链接的关系

页面访问接口和外部链接必须分开：

```text
页面数据、权限、状态、图片元数据 → Frontend API Client → 同源 /api
打开 Redmine 任务               → LinkBuilder → 外部 Redmine URL
打开产物                         → Artifact URL → 后端鉴权/短时签名
```

不要为了读取 Redmine 页面而在浏览器中直接 fetch Redmine；这样会同时引入 SSO、CORS、cookie 和权限泄露问题。

## 6. 前端数据契约

所有页面接口使用统一 envelope：

```typescript
type PageEnvelope<T> = {
  data: T;
  meta: {
    source: string;
    readAt: string;
    generation: string;
    stale: boolean;
    staleSources?: string[];
    errors?: Array<{ source: string; message: string }>;
  };
};
```

资产、任务和产物只返回页面需要的摘要：

```typescript
type AssetSummary = {
  id: string;
  name: string;
  fashionIds: string[];
  itemIds: string[];
  stage: string;
  status: string;
  redmineIssueId?: number;
  thumbnailArtifactId?: string;
  updatedAt: string;
};

type ArtifactRef = {
  id: string;
  kind: "thumbnail" | "preview" | "source";
  url: string;
  mime: string;
  width?: number;
  height?: number;
  contentHash: string;
};
```

前端请求规则：

- 每个请求使用 `AbortController`，切换筛选时取消旧请求。
- 相同 query 使用缓存，但必须以 `generation` 区分不同同步结果。
- 加载、空数据、过期、部分失败和完全失败使用不同状态组件。
- 401/403/404/409/429/5xx 分别处理，不统一显示“加载失败”。
- 页面不读取后端原始路径、命令行、P4 client 或内部磁盘盘符。

## 7. 分步实现顺序

### Step 1：建立视觉基线

- 保存当前页面四个主视图的截图、关键数量、筛选项、表头和状态颜色。
- 建立个人版主题 token，不先复制全部 CSS。
- 验收：主题替换品牌色和标题时，不需要修改业务组件。

### Step 2：先实现 AppShell 和 URL 路由

- 创建 `AppShell`、顶部状态、主导航、错误边界和统一加载状态。
- 创建 `/calendar`、`/progress`、`/analysis`、`/catalog` 路由。
- 建立 query schema 和路由恢复测试。
- 验收：刷新、复制链接、新窗口打开都能恢复同一视图和筛选条件。

### Step 3：实现 API client 和 LinkBuilder

- 将 API base URL、Redmine host、产物策略放入环境配置。
- 实现统一 envelope、超时、取消、错误映射和 stale 状态。
- 实现 `LinkBuilder` 和安全 URL 校验。
- 验收：切换环境只改配置，不改页面组件；非法 issue ID 不生成链接。

### Step 4：实现日历

- 先使用固定 fixture 完成表格、分组表头、筛选、详情抽屉和导出。
- 再接 `calendar_view`。
- 验收：日期、计划/实际/覆盖状态和详情血缘正确显示。

### Step 5：实现制作进度

- 先实现阶段定义驱动的宽表格，再实现行虚拟化和冻结列。
- 接入缩略图、阶段状态、Redmine 链接、评论和详情抽屉。
- 验收：大数据量滚动流畅；图片失败、任务缺失、阶段未知都有状态。

### Step 6：实现甘特图和分析

- 先完成时间轴模型和 `GanttBarModel` 单元测试。
- 再实现 sticky 任务列、月份/刻度层、今天线、任务条、未定日期列表。
- 最后接入筛选、成本计算入口和 CSV 导出。
- 验收：周/月/季度/年切换不改变任务日期语义；任务条可安全跳转 Redmine。

### Step 7：实现外观目录和资产详情

- 实现服务端分页、筛选、男女配对展示和登记状态。
- 加入资产详情、来源血缘和产物预览。
- 验收：列表首屏不加载完整产物；配对不一致时明确告警。

### Step 8：性能、可访问性和异常态

- 对宽表、甘特图、图片列表执行性能测试。
- 检查键盘导航、焦点、aria-label、颜色对比度、模态框 Escape 关闭和焦点恢复。
- 验收：API 断开、慢响应、过期数据、权限不足、空结果和部分来源失败均可操作且可解释。

### Step 9：替换成个人功能

个人功能优先替换以下配置和读模型，不修改底层访问规则：

- `theme.ts`：品牌色、标题、logo、状态颜色。
- `routes.tsx`：功能面和 URL。
- `stageDefinitions`：个人生产阶段。
- `LinkBuilder`：个人任务系统或文档系统链接。
- `PageEnvelope`：保留数据新鲜度和来源字段。
- `features/*`：替换页面内容和业务动作。

## 8. 必须重点防止的问题

### 8.1 不要复制当前的隐患

- 不要把 Redmine host 写死在组件里。
- 不要把编辑密码放到 `sessionStorage`。
- 不要把真实工程盘路径返回给浏览器。
- 不要让一个 JSON 请求包含几十 MB base64 图片。
- 不要用任务名称、资产名称或负责人姓名作为唯一关联键。
- 不要用前端内存状态代替可分享的 URL 状态。
- 不要让组件直接拼接外部 URL。

### 8.2 日期和状态

- 所有日期字段统一 ISO 8601。
- 页面明确显示数据读取时间和来源更新时间。
- “没有数据”“数据过期”“同步失败”“没有权限”必须是四种不同状态。
- 完成、待验收、逾期、计划和未知状态同时有文字和颜色表达，不能只依赖颜色。

### 8.3 大数据和浏览器资源

- 1697 条任务和宽表必须分页、虚拟化或按可视范围绘制。
- 图片必须缩略图优先、原图按需、失败可重试。
- modal、object URL、事件监听和定时器都必须在卸载时清理。
- CSV 导出应使用当前筛选的服务端数据或流式导出，不能依赖当前 DOM。

### 8.4 安全和链接

- 外部链接只允许配置域名和 HTTPS。
- 所有新窗口链接使用 `noopener noreferrer`。
- API 负责权限判断，前端隐藏按钮不能代替权限控制。
- 不将 SSO ticket、cookie、token、密码或内部文件路径放进 URL、日志或下载文件名。

## 9. 验收清单

- [ ] 四个主视图可通过独立 URL 访问并可恢复 query 筛选。
- [ ] 页面不直接访问 Redmine、P4 或工程目录。
- [ ] Redmine 链接由配置驱动，ID 非法时不生成链接。
- [ ] 图片使用产物引用和按需加载，不返回大 JSON/base64 列表。
- [ ] 日历、宽表、甘特、目录四种可视化均有加载、空数据、过期、错误和权限状态。
- [ ] 宽表和甘特在大数据量下使用虚拟化/裁剪。
- [ ] modal、抽屉、图片 object URL、事件监听和请求都能正确清理。
- [ ] 键盘操作和屏幕阅读器标签可用。
- [ ] 当前页面的关键视觉计数、状态颜色、Redmine 跳转和缩略图行为有回归测试。
- [ ] 没有域名和 HTTPS 时，使用 `127.0.0.1:5173` + `127.0.0.1:8000` 可以完成全部前端开发和测试。

## 10. 最终建议

个人版不应从“复制当前 bundle”开始，而应从以下四个稳定接口开始：

1. `PageEnvelope<T>`：统一数据、来源、版本和过期状态。
2. `LinkBuilder`：统一内部路由、Redmine、产物和外部文档链接。
3. `ReadModel`：页面只消费已经关联好的视图模型。
4. `VisualizationModel`：表格、甘特、目录和图片预览先将业务数据转换为专门的显示模型。

这样可以保留当前页面最有价值的部分——高密度表格、状态可视化、甘特时间轴、抽屉详情和外部任务跳转——同时避免它的几个限制：单 URL 状态、硬编码域名、浏览器侧凭据、大 JSON 图片和组件内跨源拼接。
