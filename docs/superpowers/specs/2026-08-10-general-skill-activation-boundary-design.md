# 通用 Skill 按需加载边界设计

## 目标

通用能力 Skill 的加载由任务相关性决定，不由任务复杂度、是否进入完整工作流或是否修改文件决定。简短只读任务也可以获得必要的代码、语言或领域增强，同时避免把能力加载膨胀成完整流程。

## 轻量边界

1. 用户明确点名 Skill 时直接加载。
2. 语言、文件或任务语义明显相关时，自动加载该 Skill 的 compact reasoning core。
3. 只有实际修改时才应用 change rules；真实副作用、高成本或高风险操作继续使用现有授权护栏。
4. 同时命中多个 Skill 时只加载能明显改善当前结论的最小集合；专项引用只有出现直接信号时读取。
5. 相关性判断保持普通语义判断，不新增数值评分、任务枚举或中央路由引擎。

通用 Skill 可以按需使用 `reasoning core`、`change rules` 和 `side effects` 三类边界；没有对应内容时可以省略，不强制机械补齐结构。

## 最小落地

- 在轻量工作流中明确“流程深度与能力选择相互独立”。
- 让 `code-quality` 覆盖只读代码理解与行为分析，并把 `analyze` 加入已有 selector。
- 让 `cpp-core` 明确只读分析只应用推理核心，不自动进入修改、构建或调试副作用流程。
- 保留现有 C++ 信号路由和专项引用机制，不增加新模块。

## 验收

- 普通代码只读分析可以命中 `code-quality`。
- C/C++ 只读分析可以命中 `cpp-core`，但不获得修改或执行能力。
- 非代码普通问答不会误触发代码 Skill。
- 加载通用能力 Skill 不会自动创建完整 Design/Plan/Review 流程。
- 现有行为测试、catalog 校验、运行时快照与安装测试保持通过。
