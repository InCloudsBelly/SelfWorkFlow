# Wiki 分档样例与评分分歧

指标、分数定义、适用状态和达标条件由[主标准](wiki-quality.md)统一规定。本页只提供样例与判分方法；不是模型效果实测。先判断内容缺失、事实错误或未核实，再选证据共同支持的最高档，不用一个好片段代表整项。

## 3、4、5 分的具体样例

以下是假设案例：4 位缓存索引的 `0x0–0xE` 表示有效对象，`0xF` 表示无有效索引；关闭缓存或没有槽位时直读。它不是实际项目事实。
3 分例假定主线已建立且没有更严重错误。4 分例须连同本项其他适用要求全部满足。5 分须有独立补充观察，不能仅重复作者答案；一条走查可支撑多项，分别写出检查结果。

| ID 与主要观察点 | 3 分缺口样例 | 4 分正文/检查样例 | 5 分新增走查证据样例 |
| --- | --- | --- | --- |
| H1 概念是否建立 | 已解释句柄的表示与基本访问过程，但没区分句柄与有效对象索引，也没说明无效值。 | 定义句柄、索引和空值的职责，讲清相互区别；用 `0xE` 与 `0xF` 作正例/反例，先备和范围可定位。 | Reviewer 自选未演示的例子，如包含 `0x7` 的句柄，能据正文解释它与索引、对象的关系及不等价条件；对本页其他关键概念也无决定性缺口。 |
| H2 因果和设计取舍 | 已解释紧凑表示减少存储，但没讲保留空值为何限制容量，读者需自行补上设计代价。 | 说明减少表示空间的依据、保留空值导致的容量约束及代价；实现事实、意图出处和推断分别写明。 | 将目标改为“需要表示第 16 个对象”时，Reviewer 能解释为何不能直接占用空值、哪些取舍须重审，并核对条件变化后的结论。 |
| H3 叙事与定位 | 执行顺序、并列事实与例外挤在长段，或必要解释藏于多篇详见，读者需自行拆步骤/补条件。 | 用清楚标题、并列清单和编号步骤充分展开；长篇机制有相应图解/伪代码，概念与条件适度强调；必要前提就近、L1 路径直接，未删因果/边界。 | Reviewer 从新问题/失败现象进入，能沿条目、图解及必要链接辨认前提、顺序、结果与例外并接回结论，不依赖选读补主线。 |
| V1 图型与机制覆盖 | 不同机制反复使用同一泛图，实际结构/接口/分支差异看不出；或只有正常路径，满池回退未画明。 | 图绑定当前场景、对象/数据/接口与问题，按职责选概念/流程/关系/UML/时序图及必要伪代码；真实差异在图中体现，同一事实可复用规范图并说明映射/限制。 | Reviewer 能指出真实差异，或依据来源说明规范图复用为何成立，追踪未演示的适用边界；不把换色/标题当差异，不杜撰差别或以图数评优。 |
| V2 图注能否解释图 | 图注仅复述标题或成功/失败，未解释本场景对象、条件和结果，读者需猜图意。 | 每图的问题、图题、对象/符号/读序、条件/结果/回退及适用单位/坐标有说明；结合当前实例追踪，并说明结论和示意边界。 | Reviewer 自选一个适用实例/分支，能据图和说明定位具体结构/接口、预测结果，再核对正文/来源；未靠背景补关键关系。 |
| V3 呈现与无图可读性 | 已确认字体不符、列表标记不可辨、长路径截断、图标签拥挤或仅靠颜色；若尚未渲染/核验则记未核实，不假给低分。 | 实际宽度检查正文/图注/图内文字、中文与西文指定字体、强调/底色、列表和长标识符；保留图源及无图等价信息，记录真实回退，未满足指定要求不称已达标。 | Reviewer 用无图文本完成相同解释，再核对图中关系/数值；在目标阅读场景核验字体/样式及复制完整性，语义与呈现一致，不以 CSS/XML/Markdown 可解析替代。 |
| A1 数据与接口契约 | 已讲两端的数据表示，但无效输出何时交给消费者、由谁处理仍需回源码补齐。 | 类型、单位、有效范围、空值及适用布局完整；producer/consumer、生命周期和接口前后置条件两端吻合，有边界例子。 | Reviewer 从文档独立抽出数据/生命周期契约，选一个未演示的适用边界值，能确定两端结果及不变量，再与源码核对。 |
| A2 算法、条件与设计边界 | 正常路径已逐步讲清，但满池时是失败、回退还是产生可消费结果尚未讲明。 | 算法、判断顺序、有效配置、正常与失败出口完整；各实现单元的设计/边界问答经源码裁定，适用同步/跨帧语义明确。 | Reviewer 自选未演示的条件组合或反事实，能依据正文判定执行路径、有效产物或被破坏的前提，并核对代码；不只复述作者问答。 |
| A3 实施、修改与验收 | 最小搭建顺序已给出，但其中一步的产物、验收和失败恢复缺失。 | 给出最小依赖、建议搭建顺序、联动修改、每步验收及恢复；实际调度与搭建顺序分清，源码检查与运行结果分别记录。 | Reviewer 完成一项文本迁移/修改任务：如扩展索引容量，能列出须联动的表示、两端、缓存及验收变化，并发现省略步骤的后果；未执行代码不冒称复刻成功。 |
| A4 语义可抽取与关联 | 主要契约可抽取，但一个决定分支的值指代不明，或必要契约与选读混放，Agent 不能确定应追哪些依赖。 | 术语、符号、字段、变量和稳定锚点明确；问答具有问题 ID、条件、直接答案、依据类别及来源；必要契约、选读与证据区分，链接直达相应版本/章节，当前实现条件和答案不靠递归引用补齐（L1）。 | Reviewer 抽取契约/问答和有界的必要依赖后逐项回查，能跟随必要链接到明确停止位置，条件、单位、范围、例外与来源无丢失；不以可解析或少链接代替语义核对。 |
| E1 事实、来源与证据边界 | Reviewer 能用现有授权来源核对事实，但正文关键结论只有“见源码”，缺可追踪定位；若来源本身不可获得，则应为 null。 | 关键结论有版本/路径/符号或材料出处，事实/意图/推断/未知分开；来源核对与未执行验证均真实，冲突就近说明。 | Reviewer 对已列高风险结论反向追证，并检验一个可能越过证据范围的命题，例如“4 位编码证明硬件上限”；能明确拒绝来源不支持的外推，且不误拒已证实结论。 |
| E2 组织、跨页与维护 | 页面正文可读，但未接入主题入口，或必要链接的规范位置/锚点有误、相似版本未区分。 | canonical、导航、内外链接目标、同版本契约和维护注记完整；链接描述与实际目标/访问条件相符，有效旧文/旧图保留，跨页结论一致。 | Reviewer 从问题/症状直接定位适用版本与规范章节，组合必要契约完成任务；对假设的来源接口变化，能定位受影响问答/图文，不实际启动监控或改源码。 |

补充问题须处于文章声明范围内。Reviewer 先据候选及显式契约给出答案，再核对来源；已有源码暴露如实说明。记录问题/输入、正文位置、可观察答案、核验和限制。导航/来源页按职责选任务，不强造算法。
L1 的必要跳转与正常互链按[链接方法](link-clarity.md)检查。仅缺 5 分增量与缺必需证据的区别，按主标准统一处理。

## 同一缺口影响哪些指标

每个缺口保留一个 ID，按实际受损能力分档；不把一次问题当多次固定扣分，修订只复核影响项。

| 例子 | 合理处理 | 不应采用的处理 |
| --- | --- | --- |
| 已核实源码有满池回退，正文漏写 | A2 记录无法确定分支的缺口；H2 仅在因果解释也被截断时受影响；V2 仅在图注/图确有遗漏时受影响。 | 因同一个缺口自动把全部十二项都降档；来源已经充分仍无理由降低 E1。 |
| 断言空值编码是硬件上限，但来源不支持 | E1 记录无依据外推；H2/A2 如依赖这一断言解释取舍或扩展边界，同样记录影响；核心错误按主标准处理。 | 把一句话分别当作多个无关缺陷反复扣固定分；用其他高分抵消核心错误。 |
| 图内标签重叠，但正文与等价表格完整 | V3 按实际可读性缺口处理；其他指标保留其各自已验证结论。 | 因图不好读直接认定算法、事实与实现契约全部错误。 |

## 分歧处理

1. 保留作者分、独立分、分歧检查点与证据，核对候选/来源版本和适用性。
2. 当前 Reviewer 对照样例给出最高可支持档，说明缺的是正文、必需证据、5 分增量还是小改进；补证或修文后只复核分歧及影响项。
3. 作者不能用自评分覆盖独立分，不取平均或小数折中，不另建 Reviewer 或要求用户逐项裁决。影响达标的分歧未解决时不报达标；样例不足留作规则维护问题，不悄悄降低目标。
