# Wiki 图解规范

- Wiki 新增或实质更新技术主题时，主动逐页、逐关键机制规划配图，不等用户再次提出
  “加图”。数据结构、数据对齐、空间关系、投影关系和性能优化原理默认用图辅助解释；
  一个页面有多个独立难点时可配多图，尽可能覆盖有解释价值的机制，不以一张总览图代替
  关键细节，也不设固定张数或以数量充当质量。已有图能讲清时复用或补充。
- 流程图、思维导图和概念关系图同属默认图解手段：有多步骤、条件分支、回退或循环的
  机制主动配流程图；有多个相互关联概念、分类或层级的主题主动配思维导图/概念关系图。
  同页可组合这些图与布局/空间示意，各自回答不同问题；按解释收益选用，不强制每页齐备。
- 用户明确要求全库可读性增强时，逐页检查全部 Wiki Page，不能只抽样或处理少数专题；
  规划记录每页/章节要解释的问题、图型、来源、复用/新增及缺口，无配图收益的页面简述
  原因。普通主题更新只覆盖获授权的页面和必要导航；只读浏览、纯链接/措辞修正不触发
  全库补图。导航和来源页按阅读路径、来源/版本关系选图，不套技术页配图数量。
- 默认沿用浅色底、白色分区卡片、深色中文标题与标签、清晰留白的技术概念插图风格；
  用少量稳定的蓝、绿、橙、灰区分类别/状态，辅以文字、形状或线型。按需使用细网格、
  虚线包围边界和并排对照，让具体对象、区域和变化可见；不锁定色值、像素尺寸或装饰。
  用户另有要求或现有图形体系清晰时服从相应风格；源码符号、公式和单位保留准确写法。
- 技术机制配图默认优先使用 Agent 直接编写、可编辑并可版本管理的 SVG 概念示意图，
  精确控制几何形状、中文标签、配色和布局；保留可维护图源，不只交付栅格截图。
  沿用已有清晰图形的视觉语言，但不要求无收益地重绘现有合格图，也不绑定专用绘图 Skill。
- 空间、视锥、覆盖、缓存布局、分层和生命周期等内容优先考虑直观示意：俯视/截面、区域
  叠加、分层布局、前后对照、时间轴或设计图；真实顺序与依赖才适合流程图。图像选型服务于
  理解，不为装饰配图，也不把所有关系强行画成流程图。
- 用空间布局、包围区域、分组与小规模具体例子解释机制，例如“一个组跨多个存储页、一个页
  容纳多个组的部分”。关系、映射与容纳关系不能仅用串行方框和箭头代替；例子必须说明
  对应概念及抽象边界，不能暗示虚构的分配算法、真实容量或运行结果。

## 场景差异与每图说明

1. 每张图绑定本节的具体问题、应用场景和来源：画出实际对象/结构/接口、输入与状态、关键关系/条件、产物和边界。与相邻或近似图比较，说明这张图新增解释了什么，不能只换标题、标签颜色或卡片顺序。
2. 可以复用图源、统一视觉语言和正确的基础模型；不同场景须有真实的结构、数据、分支、交互或边界差异。近似概念优先用同尺度对照图明确异同；确实是同一事实可引用规范图，并在使用处解释映射与适用限制，不反复贴无增量副本。
3. 每图有图题和文字说明：先说要解决的问题，再解释对象/符号/关系与阅读顺序，结合本场景的具体例子说明如何得到结果，最后标明结论、原因及限制。图题不代替图注；不能让 Agent 只看图片猜接口和数据含义。
4. 长篇流程/结构讲解与对应条目一起配图；必要时补 UML、时序图或伪代码，明确输入输出、调用/生产消费与状态变化。只画真实关系，不为差异化杜撰算法、字段、容量、同步或收益。

示意：同为缓存专题，布局图回答字段怎样摆放，生命周期图回答谁何时创建/失效；不能反复用“输入→缓存→输出”代替二者。若确实共用同一布局，可引用规范图并解释本场景参数/限制，再用适当图型表达其他差异，不虚构不同结构。

按机制选图，以下是优先选型，不是每页必填模板：

| 要解释的问题 | 优先图型与应标清的信息 |
| --- | --- |
| 概念体系、分类与关联 | 思维导图组织中心问题、子概念、职责、边界和章节入口；概念关系图标明“属于/包含/依赖/关联”等关系，区分分类、组成和调用，不把所有关联硬画成父子层级。 |
| 算法、处理过程与决策 | 流程图标明入口/输入、步骤职责、判断条件与分支标签、循环/终止、失败/回退和输出；并行/等待须明确，不以箭头暗示不存在的串行顺序。 |
| 数据结构与接口的静态关系 | UML 类图/组件图或等价关系图，标明职责、继承/实现、聚合/引用和所有权；与实际类型/字段对应，不把关联都画成继承。 |
| 调用与数据交接 | 时序图、泳道图或数据流图，标明参与接口、调用/返回、producer/consumer、数据形态与失败分支；并发、等待和跨帧关系有来源。 |
| 数据结构、内存布局与索引 | 字段/位域条带、连续记录或映射图；标明字段宽度、单位、索引/偏移、stride 和记录边界，串起生产与消费位置。 |
| 数据对齐、填充和跨块访问 | 对齐前后或多记录对照；区分有效数据、padding、基址、对齐边界与步长，给出越界/错位或跨页的小例子。 |
| 空间、包含、覆盖和层级 | 俯视/截面、网格、包围区域或分层图；区分对象、包围体、候选区域及实际参与范围。 |
| 投影、坐标和采样 | 相机/视锥、投影平面与坐标变换对照；按需标坐标系、方向、裁剪与采样位置，不把不同投影或“候选”与“最终可见”混为一谈。 |
| 性能优化、缓存和裁剪 | 相同输入下的前后工作集、访问/计算范围或更新条带对照；讲清减少了哪部分工作、为何正确及新增代价，不编造耗时、带宽或收益比例。 |
| 调度、同步与生命周期 | 真实依赖图、时间轴或状态图；区分先后、并行、等待、失效和释放，不用时间顺序替代空间关系。 |

- 字段、范围、几何、箭头与边界例子必须有正文/来源依据；缺证据时标明未知或示意，
  不为补图新增技术结论。性能图中的大小、条长或数量若只是示意须明确说明，不能暗示
  实测比例；有实测值时就近标出环境、单位和来源。
- 流程图、思维导图和概念关系图可使用 Mermaid 或可编辑 SVG，以实际 Viewer 支持为准；
  保留图源并检查呈现，图旁给出可由人和 Agent 读取的概念关系或分支步骤说明，不以图替代
  正文定义、关键条件和实现契约。复杂图按概念层次或子流程拆解并互相定位。
  照片、艺术性插图等确需位图时才使用
  imagegen，数据图表按相应绘图方法处理。不能以自动流程排版或生成式位图替代需要精确
  标签与布局的技术概念图，也不因优先 SVG 而把其他合适图形一律改写。
- SVG 保持文字可读、缩放不失真，提供 `viewBox`、`title`/`desc` 或等效可访问说明；
  不包含脚本、事件属性、`foreignObject` 或外部资源依赖。独立图源与正文内联副本同时
  存在时须保持一致；在正文实际阅读宽度检查标签、图例、边界与留白。
- 图内文字和图注遵循[正文契约](article-contract.md)的中文/西文字体与适度强调要求；图形底色、代码底色和主题文字保持对比。UML/Mermaid 等须在当前 Viewer 真正渲染或提供可维护的等价矢量图，不能把图源块当作成图验收。
- 图前说明要回答的问题，图后解释读图结论；提供图例/文字说明，标明示意、非比例、坐标、
  单位与抽象边界（按需）。符号、色彩和箭头含义应一致，不能只依赖颜色传达信息。
- 图文与来源结论相互核对，不能把抽象图当真实算法、精确比例或已验证运行结果。检查
  标签可读性、裁切、重叠、资源引用和版面；能渲染时实际检查，未渲染明确记录，不能以
  SVG/XML 解析通过代替视觉检查。图内文字、图注和替代文本同样适用可读规范。
- 插图增强保留仍有效的原文、旧图和版本边界，将图置于所解释的章节附近；发现原文错误
  时沿既有证据与候选修订规则处理，不借配图静默删除或改写结论。整页内联多图时为 SVG
  ID 使用独立命名空间，避免图例、箭头和可访问说明互相引用。
