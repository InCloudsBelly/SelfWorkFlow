# 个人 Wiki 质量评价标准

标识：`personal-wiki-deep-clarity-v5`。本次增加场景化图解、结构化表达及字体/强调/底色检查；十二项 ID、权重、分数范围和数值门槛不变。本页统一管理指标和达标条件，每次评价绑定规则、候选、关联契约及来源版本。

目标是事实准确、边界明确、解释充分、人类易懂、Agent 可实施。保留因果、算法、例子、反例和必要上下文，不以字数、Token、图数、链接数或问题数评优。规则紧凑不等于 Wiki 正文简略。

## 1. 适用范围与统一口径

- 新增、实质更新或明确评估技术 Wiki：检查全部适用项。导航、来源及非技术页按职责决定适用项，不整表豁免；措辞/链接修正只复核影响项。
- 只处理授权页面、主题、来源和版本。全库任务逐页评价并核对遗漏；汇总分、抽样或已列条目全部合格都不能代替承诺范围完整。
- 本文中的**实现单元**是具有独立职责、输入输出、不变量或适用条件的机制，不按函数/文件机械计数。
- **关键缺口**指会导致理解错误，或无法确定实施所需的输入、条件、步骤、输出、边界、失败处理或验收。已确认缺失时，受影响指标最高 3 分；决定正确性的事实错误按 0 分处理。

先区分以下状态，再评分：

| 状态 | 含义 | 分数与计分 |
| --- | --- | --- |
| 已检查 | 内容和必要证据已核对；也包括已确认内容缺失或有错误。 | 按实际情况给 0–5 分，保留适用权重。 |
| 未核实 | 所需来源或必需检查缺失，不能判断是否满足要求。 | `unverified`，分数 `null`；保留权重，受影响维度及总分为 `null`，不得报达标。 |
| 不适用 | 该检查确实不属于文章职责或实际机制，已说明理由并由 Reviewer 核对。 | `not-applicable`，分数 `null`，排除相应指标权重。缺来源、未写、未渲染、没时间或工具不可用均不算不适用。 |

一项包含多个检查点时，只排除有理由的不适用检查点，不因其中一项不适用而豁免整个指标。仍有必需点无法核验时，该指标记未核实，并保留已知缺口；不能把部分检查说成整项完成。已有合格内容/图是复用并评价，不是不适用。

## 2. 十二项指标

总权重 100：人类理解 30、图解理解 20、Agent 实施 35、可信与维护 15。每项都记录正文/图注位置、检查方法、观察结果和缺口。

| ID | 名称与权重 | 必查内容 | 验收观察 |
| --- | --- | --- | --- |
| H1 | 概念理解 8 | 问题、读者、先备和范围；概念的定义、用途、组成、职责、近似概念区别、正例/反例；先概念后符号。 | 读者不看源码也能解释是什么、为何需要、与什么不同、何时适用；不以术语翻译或循环定义代替解释。 |
| H2 | 因果与取舍 12 | 约束→设计、输入→结果；取舍、不变量、失败条件、限制、替代方案依据；事实与推断分开。 | 能解释为什么这样做、条件变化后怎样、何时失效，理由具体且有依据。 |
| H3 | 叙事与阅读路径 10 | 分层主线与充分讲解；并列事实分条、操作按步骤编号，长篇机制配相应图解/伪代码；关键概念、条件和结论有适度强调；保留算例/边界/反例及 L1。 | 能辨认事实并列、执行顺序、输入输出和边界，不需从大段文字拆步骤；不以缩写、漏讲或多页往返换取短文。 |
| V1 | 图型与场景覆盖 7 | 按流程、概念/关系、结构/对齐、空间/投影、缓存/优化和接口交互选图，按需用 UML、时序图及伪代码。图绑定具体场景/对象/问题；有真实机制差异时须表达差异，同一事实可引用规范图并说明映射/限制。 | 能看出当前数据结构和接口怎样作用；不复制泛图替代不同机制、不以换标题/颜色充当差异，也不为制造差异杜撰事实或机械凑图型。 |
| V2 | 图注与图文一致 8 | 每图有问题、图题和说明：对象/符号、关系/分支、坐标/单位、边界与读序；结合本场景例子解释结果、原因和不能推导的内容。 | 能把图中元素对应到当前结构/接口/步骤并追踪实例；分类/组成/依赖、先后/并行、候选/最终、示意/实测分清，图注不只重复标题。 |
| V3 | 呈现与无图阅读 5 | 实际宽度下核对正文/图的字体、强调、对比度、底色、列表标记、图例、裁切/重叠与长标识符；保留可编辑图源和非颜色的可访问说明。 | 中文按仿宋_GB2312，数字/西文/符号按 Times New Roman；精确标识有可辨底色且完整可读、可复制。记录实际字体/回退及渲染，不能仅凭 CSS 声明判通过；无图仍有关键关系/数值。 |
| A1 | 数据与接口契约 10 | 下列 A1 检查点。 | 不猜字段、默认值、生命周期或生产消费约定即可建立相容接口；两端及边界例子相互吻合。 |
| A2 | 算法与设计边界 10 | 下列 A2 检查点，并完成逆向质询。 | 正常、失败和边界路径可走通，条件与每步有效输出明确；关键算法没有黑盒步骤。 |
| A3 | 实施与复现 10 | 下列 A3 检查点。 | 仅凭正文及显式契约可列出实施、修改、验收和恢复步骤，知道何处必须联动。 |
| A4 | 语义抽取与依赖 5 | 稳定标题/锚点、统一术语、精确符号及解释；枚举分支、表格字段、公式变量、例子和简化边界；问答 ID/直接答案/条件/依据类别/来源；L1 必要依赖及版本。 | 不靠截图、颜色、指代、私聊或自行查源码补答案；可抽取输入输出、约束、步骤、边界、验收和依赖，语义不丢失，引用可结束。 |
| E1 | 事实与证据 10 | 授权来源、路径/符号和版本；图文核对；实现事实、已记录意图、解释性推断、冲突/未知分别说明；源码、静态、视觉、编译/测试和运行证据分开。 | 结论可追溯且不超出证据；代码行为不冒充作者动机，未执行不说通过，计划不说成运行/复刻成功。 |
| E2 | 组织与维护 5 | 规范主题位置（canonical）、导航、内外链接/锚点/版本/访问前提及跨页一致性；有效旧文/旧图、版本边界和维护注记。 | 入口明确，无断链、重复矛盾或描述与目标不符；正确性限制就近保留，精确维护身份后移后仍可核验。 |

**A1：只核对实际存在的数据和机制。**
- 数据：类型、语义、单位/坐标、精度、容量、无效值、布局、对齐、步长。
- 生命周期：归属、初始化、生产、消费、更新、失效、释放；必要线程/队列约束。
- 接口：职责、输入输出、前后置条件、副作用、返回/提前退出、产物有效时机、失败时消费者处理。
- 紧凑机制：位打包、压缩、索引映射、池化、缓存、工作列表裁剪的位宽/范围、编码解码、精度/容量、不变量与两端；收益/代价区分设计预期和实测。

**A2：分别解释算法、时序和环境条件。**
- 核心公式/变换、必要短实现或明确简化的伪代码；分支顺序、提前退出、同步、并发、跨帧状态。
- 源码版本/工作区差异及适用环境；相关 Platform、RHI、Feature Level、Shading Path、材质/视图、宏/CVar。
- 编译支持、运行准入、实际有效值、条件组合、优先级和不满足时的回退/禁用，不混为一个开关。
- 各实现单元的目的、前提、不变量、反事实和边界经代码核对，最终问答写进正文。

**A3：给出可执行的说明，但不冒称已执行。**
- 最小依赖、搭建/移植顺序、每步产物和验收；建议搭建顺序与实际源码调度顺序分开。
- 路径/符号及上下游；适用的资产/构建产物、序列化/ABI、CPU/GPU 布局、Shader permutation、缓存/历史状态（cache/history）、最终消费者的联动与兼容/失效风险。
- 复现目标、环境/输入、配置、观察点、预期/误差、失败信号、清理/恢复；命令和取值有来源，待填项说明取得方式。
- 条件变化时区分可调参数、配套约定和算法前提；正常、失败、边界及实际存在的关闭/回退、容量、跨帧/失效路径有验收出口。

L1 是 H3/A4 的共享检查点，不另加权：必要时提供内外链接，区分必要契约、选读和证据，直达适用章节/版本；本页主线在声明先备内完整。允许清晰导航、正常互链和必要多层先备，不以链接数或网络边数评分；不能删知识或证据来减少跳转。E2 检查目标，E1 检查证据。

## 3. 分档、计分与达标

已检查项按全部适用检查点共同支持的最高整数档评分，不取检查点平均，也不按缺陷数量机械减分。具体样例见分档方法。

| 分数 | 判定 |
| --- | --- |
| 0 | 本项整体缺失，或存在决定正确性的错误，无法据此理解/实施。 |
| 1 | 只有名称、结论、框图或引用。 |
| 2 | 有部分解释，但重要关系、步骤、字段或条件仍需补齐。 |
| 3 | 主线基本可懂，但解释、组织或呈现仍有实质缺口，需要读者自行补条件、拆步骤或对照材料。 |
| 4 | 全部适用要求完整、准确、可定位，已通过对应走查；只剩不影响理解/实施的小改进。 |
| 5 | 满足 4 分，并以独立补充问题、条件变式或语义抽取验证迁移使用；关键难点有充分因果、例子/反例和必要图文，无隐含关键前提。 |

仅缺 5 分的补充证据时，可按已完成的 4 分要求评分；若缺的是必需来源或检查，仍为未核实。已披露原始动机未知，但实际行为/边界已核实、推断明示且无关键缺口，不因此扣分。

默认追求适用项 5 分。报告达到个人标准，须同时满足：
1. 每个适用指标至少 4 分；每个有适用项的维度至少 90/100；总分至少 95/100。
2. 范围已复核，必要单元/条件和理解/实施无未关闭关键缺口；必需检查有证据，小改进有处置。
3. 独立 Review 通过。自评分不代替独立评价，影响达标的评分分歧未解决时不报达标。

对单页或规划时明确的评价单元计算，保留原始分数/分母，不四舍五入后判通过：
```text
总分 = 100 × Σ(适用指标权重 × 指标分数 / 5) / Σ(适用指标权重)
维度分 = 同一公式，仅取该维度内的适用指标
评价覆盖（评分项） = 已评分适用项数 / 全部适用项数
适用权重覆盖 = 适用权重 / 原始权重100（同时列出各维度分母）
```

一项未核实则受影响维度/总分为 null；没有适用项的维度标 not-applicable，不给满分；整表无适用项不算总分。不同文章类型或适用集合不直接排名。全库达标须承诺范围每页分别达标，抽样不得外推。

**必须满分的情况。** 当某项从 5 降到 4，即使其他项全 5，维度损失为 `20×该项权重/该维度适用权重`，总分损失为 `20×该项权重/全部适用权重`。该项权重超过维度适用权重的一半，或超过全部适用权重的四分之一时，该项实际必须 5；等于边界仍按公式判定，多项降分累计。

| 情况（其余必需检查通过） | 总分 | 维度分 | 数值门槛 |
| --- | --- | --- | --- |
| 十二项适用，A1=4，其余=5 | 98 | Agent：3300/35≈94.2857 | 满足。 |
| 十二项适用，E1=4，其余=5 | 98 | 可信：1300/15≈86.6667 | 不满足；E1 必须 5。 |
| 某维度仅一项适用，该项=4 | 依其余项计算 | 80 | 不满足；该项必须 5。 |

规划时标明实际满分项。不得因低分事后改适用性、降低目标或缩小承诺范围；合理调整须留依据并复核。核心错误、误导图文、关键字段/分支/同步/步骤缺失、证据不可追踪或虚称运行，均不能被平均分抵消。质量分不替代授权、来源、Review 或发布门禁；协议允许带缺口发布时仍明确未达个人标准。

## 4. 执行与记录

1. **规划**：绑定范围、读者、适用项、来源、正文/图注/问答位置和实际满分项，建立预期单元与条件清单。
2. **写作**：充分讲解概念、因果、例子、实现和边界；技术主题先据绑定文档提问，再核对代码，修正文图并固化问答。
3. **独立审查**：先仅凭候选与显式同版契约完成下列走查，再核对来源和范围；不靠背景或源码知识补正文。已接触来源如实披露，不声称盲测。
4. **修订交付**：按证据处理分歧，只复核受影响项和未关闭问题、重算相关分数；沿既有发布流程。

技术实质更新须覆盖全部关键机制，可复用贯穿例子，复杂主题增加用例：

| 走查 | 必须完成的观察 |
| --- | --- |
| 人类理解 | 解释关键概念的定义/用途/区别与例子；复述问题、关系、因果、取舍及边界/反例；按 L1 检查必要跳转后能接回主线。 |
| 图与图注 | 逐张检查本次新增/改动图的问题及具体对象/关系/分支；核对分类/组成/依赖、条件/回退/终止和正文/来源。实际阅读宽度下另查标签、裁切、重叠及资源，披露全部/抽样和未查范围。 |
| Agent 实施 | 从输入/环境/布局走到步骤、中间产物、消费者与验收，含正常及适用失败/边界；独立质询设计前提和变化结果，按 L1 抽取有界依赖/版本，列出无法确定项及影响，再核对代码。 |

文本、视觉、源码/静态和编译/测试/运行结果分开。未运行本身不降低文本质量；需要运行证据才能成立的结论未核验时，相关项仍为未核实。不因评价额外授权编译、清缓存、实验、业务代码修改或扩大来源。

每项记录适用性、分档理由、正文锚点、方法、可复述观察、证据/版本、缺口和修订。共用证据可复用；同一缺口只影响实际受损的指标，各自说明，不平均作者分与独立分。
范围、规则、候选、关联契约或来源变化，只复核受影响项。旧评价升级 v5 须补查相对原版本新增的要求，尤其 H3/V1/V2/V3 的结构、场景和呈现检查；未变证据可复用，不能直接改标签宣称升级，旧绑定/回执保留。95 分是约定质量索引，不是 95% 理解率或实施成功率；格式解析、关键词与模型置信度不代替语义走查，示例不代表已完成效果校准。
