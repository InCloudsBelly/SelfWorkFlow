# 工作流与 Skill 维护

沿核心的目标、授权和证据边界，处理命中职责及必要引用；以下为取舍指导，不自动开启 TDD、独立审查、字段表或模型评测。

先区分用户意图、授权/安全边界、完成依据、可选方法与实际工具前提。已有覆盖先解决歧义、默认路由或相互冲突；方法自主选择不能靠一句总则忽略残留强制规则，需同步修改普通任务实际可达的 owner。不把个案、关键词或固定轮数升级为全局规则。

用有辨识力的正例、邻近反例和必要的歧义案例检查含义；例子是核对手段，不要求每次维护生成一套流程材料。已有明确要求优先，支持的隐式调用不因维护自行关闭。只改所需来源，保留上游许可、版本和来源锁；缺失或漂移如实报告，不用旧安装替代。

新增实质能力或需要创作/评测方法时，可沿绑定根参考固定 `references/anthropic-skills/skill-creator/`；文档入口为 `METHOD.md`，runtime 为 `SKILL.md`，其他角色/schemas 只在确需时读。源码材料按 repositoryRoot 的 `dependencies/locks/anthropic-skills.lock.yaml` 和固定 submodule 取，不擅自升级上游。

验证与改动相称，核对生效边界、引用、生成或消费结果。成本优化时比较实际加载与调用开销，必要时记录字符变化；常规措辞修订不强制重建整套指标。静态检查、构造场景和真实 Agent/部署试验分别报告；没有真实对照不声称 token、费用或行为收益，不自动追加模型对评、hooks、CI 或新规范。

仓库规定的生成、检查、自包含发布包及旧 revision 保护仍是实际交付要求；安装、迁移在途、远程发布或消息另按其授权处理。交付给出结果、必要证据与缺口，不把维护规则扩散为日常任务义务。
