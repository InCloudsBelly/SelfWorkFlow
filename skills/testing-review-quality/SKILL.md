# 测试与验证

依据任务完成标准、误判后果和实际受影响行为选择验证方式；可复用仍有效的结果，不因行为变更自动要求 TDD、固定测试层次或额外审查。用户/项目明确指定的方法和门禁须遵守；所需能力缺失时报告缺口，不自行降低保证或冒充通过。

优先获得能区分正确与错误行为的证据。现有测试、针对性自动化、静态检查、实际消费者观察或人工步骤可按任务组合；对关键持久化、恢复或真实交互的结论，不能仅以 Mock、命令成功或内存状态代替对应结果。预期应来自需求和行为，而非照抄实现；Mock、接缝与用例范围按辨识力和维护成本取舍。

TDD 适合有清晰行为和可执行反馈的任务。明确采用时，RED 须实际因缺失行为失败；修改后在可比输入与环境下复跑同一失败测试，确认通过后再作必要回归。环境、语法或夹具错误不冒充 RED。需更具体示例时，沿绑定根参考 `methods/matt-pocock/tdd/METHOD.md`；runtime 入口为 `skills/matt-pocock/tdd/` 下的 `SKILL.md`。阅读参考不等于选择完整流程。

验证证据须对应其声称覆盖的对象、输入与环境。可复用仍适用的证据，但不能将其他对象的结果冒充当前候选及输入已验证；相关变化后复核受影响部分。

禁编译/测试时遵守限制，说明实际完成的源码或静态工作、未执行检查及其验收影响；不能虚构 RED/GREEN 或运行通过，也不要求额外状态表。交付提供判断结论所需的命令、结果和证据入口即可，不必重放所有日志。

显式 contract-managed task 或 Host 已按契约承接时，仍完整执行[契约规则](references/contract-host.md)；普通策略的自主方法不能代替其 package、receipt、runner 或完成门禁。
