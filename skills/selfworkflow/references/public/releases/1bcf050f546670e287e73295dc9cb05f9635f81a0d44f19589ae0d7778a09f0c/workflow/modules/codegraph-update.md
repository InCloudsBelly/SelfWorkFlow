# CodeGraph 更新模块

- 本模块由主 Agent 自动触发。主 Agent、子 Agent、脚本或工具产生实际源码新增、修改、删除、重命名、撤回后，按项目根目录合并本批真实路径，在后续结构化读取或交付前调用一次 `provider sync --project-root <repo> --changed-path <path>`；重命名记录旧路径与新路径。批次部分失败、提前中止或回滚留下实际代码变化也必须触发，不能只处理成功结束的编辑。
- `sync` 是写后生命周期入口：先检查忙碌状态，数据库文件确实缺失才自动 init；数据库存在但状态异常时保留并报错。已有索引执行一次官方增量 sync 核对当前文件系统。不能仅凭 status fresh 豁免核对；官方 watcher 已更新的未变文件由 SDK 跳过解析，不要求重写节点。成功完成后仍不新鲜时保留原库并报告 `not-fresh/unverified`，禁止自动执行 `index`、`index --force`、`recreate` 或删除旧库。全量重建须另有用户明确授权，并保留可恢复旧库直到新库验证完成。每次维护后验证状态；命令失败停止本次维护并报告，indexing/busy 按 `codegraph-read.md` 的共享预算等待，不启动竞争维护或无限重建。返回的 updated 表示执行了维护动作，不代表每次都有节点变化。
- 仅计划、普通文档/日志、无实际修改或官方配置不纳入的文件不触发写后维护；涉及代码阅读时仍遵循读取模块。用户手动修改和目标仓库 Git 操作由读取模块的漂移边界捕获，不要求用户另发更新指令。变更使相关旧图证据和计划假设失效；更新 fresh 后重查受影响结论。
- `.codegraph/` 是项目级可再生缓存，不自动 Git add、commit 或 push；不要手工删除它来模拟同步。用户明确要求清理旧缓存时才删除旧的 `<repo>\graft\` 目录。
- 同一批编辑不得按文件逐个启动同步。子 Agent 汇报实际改动路径，Reviewer 消费绑定证据；只有主 Agent 发起工作流生命周期调用，不额外重启 MCP 连接来同步。官方 watcher/daemon 自行维护，SelfWorkflow 不再创建后台进程或自己的事件队列。
- 同步失败必须报告阶段、动作和真实状态，图证据保留 `unverified`；停止本次失败的图维护，不停止无关工作。普通 agent-policy 可依据直接源码核对和适用测试交付，列明图证据缺口及其影响；不得把旧 CodeMap 或文本回退报告为 fresh，也不能宣称所有验证通过。仅依赖图且无法替代的验收项、显式契约的图门禁继续待验证。
