# DocHub 发布适配

明确以 DocHub 为目标的导出、提交和发布稿修复才加载本流程。按各来源的规则读取，转换产物是独立的 DocHub 发布稿。导出和提议交付本地稿件，正式提交沿 DocHub 的审稿确认流程。

## 固定来源和目标

1. 在宿主工具列表定位实际 DocHub 实例和本次所需能力。按 `apply_document_changes` 的实时定义找到《DocHub 写作与知识整理规范》和《DocHub 发布与验收规范》，用 `get_document` 读全文。系统知识库整理或需要结构参考时读《DocHub 正文模板与问答预设》。按实时规范决定字段、权限、限额和验收。缺工具或必需规范时保留本地草稿，标明缺口。
2. 确认源稿、目标实例和发布受众。读取绑定版本的全文，记录来源身份、版本或内容 hash 及核验状态。分别核对读取权限和正文、附件在目标受众中的分享许可。权限或关键证据不明时留草稿。
3. 新建或重新归类前用 `get_document_catalog` 取全量目录与标签。新建查重，更新按已核实的稳定 ID 读最新全文并核对归属。按正文匹配分类，按 DocHub 规范核实作者。更新保留未要求修改的内容、元数据和仍需引用的附件。

## 生成完整发布稿

1. 逐页建立源稿对照，覆盖章节顺序、正文、表格、代码围栏、图与图题、公式与式号、引用及附件。按完整内容适配，摘要单独写入元数据。对照稿件核对条件、结论、适用版本和可查来源，记录经授权的删减或替换及理由。
2. 用目标支持的 Markdown 表达。移除来源专用 front matter、围栏外的导出注释和空 HTML 锚点（如 `<a id=…>`）。把布局标签中的有效内容转换成普通 Markdown，表格里的 `<br>` 可改为可读分隔并保留单元格边界。单元格内的字面竖线写作 `\|`，行内代码也适用，例如将逻辑或写作 `\|\|`。表格分列使用原有分隔符。代码样例、技术文本和公式源码按原义保留。正文、附件和自定义属性排除内部事务数据、本机路径及敏感数据。
3. 以目标阅读页的能力选择媒体表达。可用经验证的原图附件，或将内嵌 SVG、Mermaid 等图块转成受支持的附件。依赖来源渲染的块公式可用公式图和可复制的 LaTeX。阅读页若把 `$…$` 显示成源码，能无歧义表达的行内公式用可复制数学记号，明确区分上下标、指数、分式分组和向量。确需排版的按原 LaTeX 用行内图或就近式块，另保留可复制原文。保留图题、式号和原文定位，逐项核对图、块公式、行内公式、附件及引用。关键内容的目标可读性无法确认时保留草稿。
4. 把 WikiLink 和相对页面路径映射到真实稳定 ID 或受众可达的授权来源。章节链接以获准的阅读预览或正式页实际生成的锚点为准，当前 DocHub 页面可见 `section-…` 形式。把旧锚点按原意映射到标题、图题、式号或来源条目，必要时用原题注生成可定位的 Markdown 标题。页内与跨篇引用均按源页、引用位置、目标页和目标章节登记，同名链接逐处匹配。首轮以普通文本保留待补引用的链接文字及章节定位，确保正文可独立阅读。正式页可读后核实真实 ID 和实际锚点，仅按已审计划回填。计划外未解析的引用留在草稿。
5. 附件只取授权根内的实际文件，核对解析后的路径、内容、文件名冲突、大小和校验值，并按目标保留规则核算旧附件与新增附件的单篇额度。用普通 Markdown 引用附件文件名，随 `assets` 按实时 Schema 提交。浏览器预览或接口读回时核对服务端改写后的引用与附件。仅在允许把完整稿和附件发往目标时使用远端 `dry_run` 核验实际载荷。

## 审稿与提交

1. 复用仍有效的内容审查，独立复核转换对正文、媒体和链接的影响。展示完整稿或可直接阅读全文的入口，以及目标、操作、元数据、作者来源、附件和补链计划。提交前按 DocHub 规范取得对具体稿件或批次的明确确认。同稿沿用确认，实质改动或引用含义变化须复审并重新确认。
2. 核对源稿和附件仍对应审阅版本，通过 `apply_document_changes` 新建或更新。更新只传改动字段，携带已读版本的 `expected_revision`。版本冲突时重读，在最新正文上合并已授权的改动并保留并发编辑。有内容冲突或合并稿有实质变化时，复审并取得确认后再提交。
3. 正式请求使用 `idempotency_key`。结果不明时先核实该批，原样重试沿用原请求和原键。原请求结果确认后，变更请求内容或版本条件时使用新键。超限按实时约束拆批，逐批保留请求与结果。

## 发布后验收

1. `published` 后按正式 ID 读回全文、元数据和附件，对照已审稿和补链计划，检查正文、媒体校验值与目标 ID。用 `search_documents` 核对正式 ID 的可检索性。保留已核实的来源与目标 ID 映射供后续更新。
2. 在有访问权限的 DocHub 实际阅读页核对逐页图与块公式是否加载，行内公式是否可读并与段落对齐，图题、式号及可复制 LaTeX 是否可读。检查正文和表格是否露出导出标记或行内 TeX 定界符，区分有意保留的源码和代码样例。逐行对照表头与单元格，核对含竖线的代码和末列说明是否完整。对本批页内与跨篇章节链接核对实际目标锚点，实点抽查代表性跳转，包括有图或公式的目标。批量核验可在阅读页 DOM 记录图片实际加载及目标锚点存在性，懒加载内容滚动到对应位置再验。
3. 分别记录发布、接口读回、检索、网页呈现、链接定位和适用的独立问答回归。`dry_run` 与接口读回只证明提交内容。网页访问或登录受阻时记录 `unverified` 和待核页，网页验收以阅读页证据为准。
