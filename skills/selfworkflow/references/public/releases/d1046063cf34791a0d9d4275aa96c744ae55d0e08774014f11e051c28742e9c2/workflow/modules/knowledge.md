# 知识操作指导

用于用户要求的知识读取、候选、更新及 Wiki 工作；普通代码、Markdown 或临时记录不自动增加知识交付。沿核心的目标、授权和证据边界，不因 profile、资料链接或稳定结论启动额外流程。

## 内容与目标

依据用户请求及既有绑定确定来源、文稿用途、范围和发布目标；来源服务不自动成为发布目标。仅作为资料的链接或已有工具能力不授权发布，明确的目标和同范围授权则直接沿用。

需要内容组织、质量或格式指导时，按缺口参考 [Wiki 工作流](../../methods/wiki-workflow/METHOD.md)；阅读不代表采用其整套流程。已有稿件沿已选用途和有效正文继续，局部维护核关联影响，不自动重写全文或增建另一套产物。代码与数学内容须以实际源码、计算及对应呈现为据；图谱使用仍遵守其[启用与新鲜度条件](codegraph-read.md)，不是通用写作前提。

未选发布后端时可交付本地候选，不推定 SelfWiki 或探测未选服务。已约定的知识发布受阻时说明尚未完成，继续其他无依赖工作，不默切目标。

## 实际后端操作

read 只读，propose 不发布。update 须处于写入授权内，并满足所选后端的来源、版本、候选、恢复与发布条件；是否需要独立 Review、审批、CAS 或专用回执由用户/项目明示要求和真实协议决定，不从普通内容更新推导固定角色。

选定 SelfOpenWiki 后按当前操作读 [SelfWiki 接线](../../methods/kg-selfopenwiki/METHOD.md)。其个人发布所需的真实候选、独立审查回执和 CAS 仍是硬门禁，不能用普通候选、自审或直接文件写入替代。DocHub 等其他目标沿相应适配，不调用 SelfWiki。缺能力、漂移或恢复问题只阻依赖动作；不猜 API、身份、OAuth 或根目录，不伪造字段或成功。

## 批量与开销

按依赖和共同来源组织工作，串行、合批、拆分或委派由实际收益与上下文质量决定，不按主题数强制创建 Writer/Reviewer，也不强制跨主题更换协作者。若协作，遵守真实独立性、只读边界和后端 PageJob/回执绑定；复用有效材料，避免各自重建相同上下文。

默认不为批量任务设置固定时长或请求数的必经检查、拆分或续接。实际出现重复工作、证据难以保持有效、上下文不足或无进展时，可整理已有状态并调整方法。时间和调用数只是线索，不是完成证明；用户预算、宿主限制及后端重试/恢复规则仍须遵守，不能因换页、主题或 Agent 重置同一故障的门禁。
