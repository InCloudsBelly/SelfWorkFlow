# Wiki 评价记录示例

[主标准](wiki-quality.md)允许紧凑记录；本页仅用户/消费者要求结构化明细或字段含义难判时读。示例不是执行证据，不是MCP状态，也不要求每页生成两套评分或大型JSON。

默认保留候选/规则/契约/来源绑定及一份覆盖清单；用共享观察ID记录输入、预期/观察、锚点、来源和限制，十二项引用它。相同理由/版本不逐项重抄；适用性例外、缺口/修订和影响达标的分歧仍逐项可追溯。

```text
规则 personal-wiki-deep-clarity-v7 @<revision/hash>
候选/契约/来源 @<各自绑定>；范围 <页/单元/条件及未查ID>
观察 O1：<自选条件→从正文推导的结果→来源裁定；章节/版本/限制>
观察 O2：<实际Viewer宽度、请求/实际字体/回退、图文/布局/复制结果>
适用时 O3：<公式对应机制、参数/约束/单位/形状/范围、假设/边界、来源与数学核对；工具执行和目标显示分别取证，可并入O1/O2>
指标：H1=<分/状态>@O1；H2=…；H3=…；V1=…；V2=…；V3=…；
      A1=…；A2=…；A3=…；A4=…；E1=…；E2=…
例外/缺口：<指标ID、适用性理由、缺口ID/影响、处置和复核结果>
覆盖：<页/评分项/单元/条件的原始计数与排除理由，未知分母=null>
维度分/分母、适用权重/总分：<原始值>；独立Reviewer：<范围及结论>
文本/视觉/运行状态：<分别记录>；decision：<unverified/revise/pass>
```

所有十二项均须有结论或有理由的不适用，示例省略号实际填写；共用观察须分别支持引用项的分档，不能只写“已检查”。覆盖含范围遗漏核对；设计边界含关键单元/问题→答案锚点、来源后发现及来源暴露；L1记录必要依赖路径/版本/停止位置；视觉含每页/改动图及公式范围、字体、底色、强调、列表、长标识观察。数学解释/参数归H1–H3，正确性/来源查A2/E1、显示查V3；工具运行、数学核对、目标显示分别留状态，非数学页不造O3，旧v6记录不改贴v7。

已有消费者要求JSON时沿其既有格式，不改协议。字段含义：applicability为applicable或有理由的not-applicable；checkStatus为checked/unverified/not-applicable；score仅checked时为0–5整数，其余null。必需证据缺失为unverified且保留权重，真实不适用才排除权重。decision先判必需项未核实，再判数值/覆盖/独立审查未达标为revise，全部满足才pass；未核实不抹掉已知缺口。

作者不必默认另出完整分数表，已有自评分不能覆盖独立分。记录留在已有任务/审查材料，不放Wiki开篇；复用原绑定、观察及受影响项复审，不为模板新增后端字段或确认。
