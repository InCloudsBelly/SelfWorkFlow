# Wiki 内容审查

按稿件面向的读者和承诺回答的问题验收，本地候选与正式稿适用同一内容标准。局部修订复用仍有效的证据，补核关联结论。明确要求量化评分或评分验收时才读[数值评分](wiki-scoring.md)，历史评分沿原绑定。

## 默认技术 Wiki 验收

| 核对项 | 通过条件 |
| --- | --- |
| 事实与来源 | 关键结论可追到获授权来源的适用版本和具体位置。实现行为查对应代码，操作步骤查手册章节或实际操作，实测性能查相应环境的测量。区分事实、推断和未知。按结论取证，全文审查、完整迁移或消除歧义需要时读全文。 |
| 理解与边界 | 原理文应让读者沿一个实际例子解释输入如何得到结果，并能判断关键条件变化后结果是否仍成立。讲清机制、必要推导、取舍和适用边界。设计动机缺少来源时，标为推断或未知。 |
| 使用与依赖 | 实施或复现须给版本、环境、输入、步骤、可观察产物及失败恢复。核对生产与消费的关键契约（如单位、布局、并发、失效）。共享契约直达适用版本与章节，区分选读与证据。导航和来源页核对可达、查找与取证。 |
| 图文与可读性 | 图表、公式和代码准确可辨，关键关系有文字解释。正文、公式与图例的记号和含义一致，公式与代码原文可取。引用能定位到所述对象。 |

使用／排障指南按[指南规则](operations-guide.md)核对读者能否找到步骤、判断生效、沿症状定位并验证处置。双套交付时分别核用途及同版事实。

有版式约定、交付实际阅读页或复杂图式等呈现发生变化时，在相应阅读环境核受影响的排版、显示、复制和跳转。环境不可用时标明待验范围。普通 Markdown 候选可直接核正文与引用。

## 审查和停止条件

- 从读者的实际问题走查稿件。只用正文和声明的先备找答案，再回查来源，核对结论、例外以及稿件完全漏掉的问题。原理文可改变一个关键条件检验解释力，指南可从失败现象查到下一项观察与恢复步骤。将找不到、答错或只能靠猜的关键答案补回正文。专题或全库审查覆盖约定页面。
- 对缺少实测的步骤或性能数字，写清已有证据能说明什么。手册步骤可作为操作依据，复现成功须有对应环境、输入和可观察结果。静态证据与运行结果冲突时先定位差异，保留尚未解决的分歧。
- 关闭误导理解或实施、缺关键条件或必要证据、阻断查找或阅读的问题。其他缺口标未核实及影响，小改进可保留。必要项有据、阻断已关即汇总覆盖与结论。
- 内容结论与发布状态分别核验。独立审查、审批、回执和 CAS 按用户或项目的明示要求、显式契约及[目标协议](backends.md)履行。正式发布核对授权、来源和已核验的候选版本。

复杂范围才读[覆盖方法](coverage-baseline.md)，难判断的反例读[边界质询](design-boundary-grilling.md)，跨页依赖疑难读[链接方法](link-clarity.md)，实际配图读[图解规范](diagrams.md)。
