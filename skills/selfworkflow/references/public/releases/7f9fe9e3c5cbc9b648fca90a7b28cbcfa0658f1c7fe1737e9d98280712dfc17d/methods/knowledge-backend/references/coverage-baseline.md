# Wiki 覆盖基准

本方法检查必要知识是否列全，计分与缺口处理统一按[主标准](wiki-quality.md)。范围限于授权主题、任务、来源和版本，不穷举整个代码库，不新增流程或权限。

## 建立与核对范围

1. **任务范围**：记录读者、承诺回答的问题/实施目标、页面、来源/版本与排除内容。全库任务列全部现有页面，并查目标中是否有尚无页面承载的部分；纯链接修正不扩成全库任务。
2. **文档预期**：仅从用户任务、绑定候选和显式同版契约列概念、入口/输入、输出/消费者、生命周期、环境/配置/状态与失败结果。必要单元给稳定 ID；文档无法判断的保留待核查。先绑定这版清单和设计问题，再核对代码。
3. **来源核对**：沿任务入口及产物核对准入/配置、生产消费、数据约定、状态迁移、失效/释放、退出/回退及关键依赖。未列机制补入基准，标明源码后发现，保留原清单；按既有代码分析规则取证，不以没有找到证明不存在。
4. **差异处理**：对照任务所需、来源实际存在、候选已覆盖三份信息。应有未写则补文图/问答；实现不支持目标则写限制；缺来源保留待核验。新增主题/来源超授权则留待决，不擅自引入，也不当作已完成。
5. **独立验收**：Reviewer 依据任务与来源检查是否漏列，不只验作者清单；先读候选再核来源。保留所查入口、条件/状态、依赖出口和限制。范围本身未确认时标未核实。

非代码、概念、导航和来源页按学习问题、概念关系、导航路径或材料版本建基准，不强造实现。实际必要机制不能因初稿未写或证据不可得而排除。已接触代码的情况按逆向质询方法披露。

## 单元与条件怎样划分

单元按独立职责、输入输出、不变量或适用条件划分。编码/解码可作为配对契约；初始化、失效、回退有独立约束时单列检查。不按函数/行数机械拆分，也不把整个功能压成不可检查的大项。

会改变结果有效性、数据含义/布局、生命周期/同步、准入/回退、兼容性或任务成败的条件，都是必要边界。按实际机制覆盖正常、空/无效输入、容量/精度、关闭/配置优先级、失败/部分成功、并发/跨帧、失效/恢复，并给代表输入、判断和预期结果。
多个条件交互会改变结果时检查必要组合；可合并为等价类的给来源依据，不盲目穷举，也不以工作量为由省掉交互。合并/拆分单元、调整条件或排除条目，保留理由、旧 ID 对应及 Reviewer 核对，不能用改分母掩盖缺口。

## 每项需要的记录

- 范围与版本：任务、读者、来源/关联契约及基准内容身份。
- 单元 ID、职责/问题、发现依据和阶段：来自任务/文档，还是源码后发现。
- 输入/入口、输出/消费者、环境/状态/边界/失败、依赖和前提由谁保证。
- 正文条目/步骤、公式、图/图注、问答 ID/锚点和共享契约；图记录应用场景、对象/接口、与近似图的差异及说明，按实际需要安排，不强制每项一图。
- 来源路径/符号/版本、走查输入、预期/观察、核验者、覆盖限制、缺口影响及处置。

状态区分已写且已核验、已写待核验、应写未写、范围待核查、不适用和超范围待决。规范章节或问答可复用，须同版、可达且满足本单元条件；使用处写清额外约束。只给源码、无效链接或层层详见，不能算可用正文承载。按 L1 保持条件与结论相连，必要链接、选读和证据用途明确。

## 四种覆盖分别报告

| 覆盖 | 分子 / 分母 | 说明 |
| --- | --- | --- |
| 页面 | 已评价页面 / 承诺评价的全部页面 | 不证明所有必要主题都有页面。 |
| 评分项 | 已评分适用指标 / 全部适用指标 | 只表示评分完成度。 |
| 单元 | 已有正文承载且已核验的必要单元 / 基准内全部适用必要单元 | 不能在范围未确认时外推为完整专题。 |
| 条件 | 已核验类别及必要组合 / 基准内全部适用检查项 | 保留分单元明细，防止只查正常路径。 |

保留原始计数、ID、未覆盖/未核验项与排除理由；分母未知不报 100%，没有适用项标不适用而非满覆盖。缺来源、未写、没时间或工具不可用仍留在适用分母。基准合理变更后记录前后差异，来源/目标变化只重查影响项。
范围待核查或存在未关闭关键缺口时，已列单元 100% 和高总分都不能证明授权范围达标；评分与协议允许的带缺口发布仍按主标准及原流程处理。

## 防漏示例

假设任务是解释缓存读取、容量和失败回退，初稿已写正常命中与关闭缓存。以下仅为方法示意：

| ID | 必要问题与发现依据 | 候选状态 |
| --- | --- | --- |
| C01 | 正常命中如何消费索引，来自任务/文档。 | 已写且已核验。 |
| C02 | 关闭缓存走哪条路，来自文档/准入判断。 | 已写且已核验。 |
| C03 | 满池时谁给空值、谁回退，来自容量任务并由源码确认。 | 来源已确认，正文未写，关键缺口。 |
| C04 | 无效索引如何避免被当对象使用，消费端源码后发现。 | 保留后发现标记；假设修订后已写且已核验。 |

单元完成是 `3/4`；十二项填过分不改变这一缺口。消费端不可访问时对应项待核验，不能删除 C04；还须核对是否漏了其他必要状态，不能因表有四行就认定列全。
仅获评估授权时交付基准、评分和拟补内容；写入、业务代码修改或实验仍需各自授权。
