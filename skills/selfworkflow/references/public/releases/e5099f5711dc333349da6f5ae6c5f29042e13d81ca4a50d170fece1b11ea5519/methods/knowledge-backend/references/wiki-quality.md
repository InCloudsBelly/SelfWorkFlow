# 个人 Wiki 质量评价标准

评价标识：`personal-wiki-deep-clarity-v1`。本文件是指标、权重、评分和达标条件的唯一文字源；
随任务绑定的 SelfWorkflow revision 一起使用。它是 Agent 直接读取的评价要求，不代表已有
自动评分器、模型效果实测或后端发布回执。修改指标、阈值和适用性时保留变更依据与版本。

## 个人目标与适用范围

Wiki 是可长期学习、推理和实施的知识正文。优先顺序是：事实正确与边界明确、解释充分、
人类容易理解、Agent 能准确实施、组织清晰。不要以减少字数、Token、段落、页数或插图为
优化目标；摘要、表格和图服务于完整讲解，不能替代决定理解或实现正确性的细节。
消除无信息增量的重复，但保留推导、算例、设计取舍、失败路径和必要的上下文。

本标准用于 Wiki 候选规划、写作、自查、独立 Review，以及用户明确要求的质量评估。
采用当前用户要求作为默认个人目标，不要求再次点名；用户明确调整目标时记录差异与
适用范围，Writer/Reviewer 使用同一份目标。不要从磁盘猜另一份个人配置或自动修改全局安装。
它只约束已授权的 Wiki 内容，不触发普通代码/Markdown 任务、只读查询、额外编译或整库改写。

- 新增或实质更新技术主题：完整评价本文所有适用指标；架构总览可以显式链接同版本的
  实现契约，但不能用“细节见源码”留下未讲解的核心机制。
- 导航、来源、非技术页：按职责确定适用项。导航重点是问题导向与可达路径，来源页重点
  是来源角色、版本和证据边界，不机械补算法。它们并非整张评分表一律不适用。
- 纯链接/措辞修正：检查改动及受影响项，复用未变的既有评价，不要求借此重评全库。
- 用户要求全库评估/增强：列出全部页面及类型，逐页给出结果；跨页专题可有总体评价，
  不能用专题或全库平均分遮盖低质量页面。批次只改变推进顺序，不缩小承诺覆盖范围。

## 十二项指标与目标

四个维度总权重为 100。表中的检查内容按主题适用；每项都应有正文/图注锚点和检查证据，
不能只给印象分。通用分档见下一节，5 分还须通过本项对应的独立理解或实现走查。

| ID | 维度与权重 | 应讲清、应检查的内容 | 高质量的可观察结果 |
| --- | --- | --- | --- |
| H1 | 人类理解 8 | 本页回答的问题、目标读者、先备概念、解决的困难、适用与不适用范围；先建立概念再引入符号。 | 读者无需看源码即可说出“要解决什么、为什么需要、本文负责哪一段”；首次出现的专用术语有解释或明确先备链接。 |
| H2 | 人类理解 12 | 从约束到设计、从输入到结果的因果链；设计取舍、不变量、失败条件、限制与替代方案依据；区分事实和推断。 | 读者能解释“为什么这样做、条件变化后怎样、何时失效”，不会只记住函数名或步骤口号。 |
| H3 | 人类理解 10 | 按问题分层的完整叙事，具体输入输出/计算例子、边界例子与反例；术语一致，章节衔接清楚；摘要之外保留充分正文。 | 沿主线可读懂，按稳定锚点可查细节；对关键例子能逐步算出或追踪结果，不依赖“显然、同理、按常规处理”等省略。 |

| A2 | Agent 实施 10 | 核心公式/变换、伪代码或必要短实现，分支顺序、提前退出、同步、并发与跨帧状态；编译支持、运行准入、实际开关和回退分别解释。 | Agent 能确定执行条件与每步有效输出，沿正常、失败及边界分支走通；没有决定正确性的算法被压成黑盒或未定义辅助步骤。 |

| E2 | 可信与维护 5 | canonical 主题、导航可达、链接/锚点与跨页一致性；有效原文/旧图和版本边界保留，精确维护身份后移而不移走正确性细节。 | 读者能找到主题与相邻契约，无重复矛盾或断链；正文先解释知识，文末可核验来源与维护身份，更新后仍可理解旧版差异。 |

以上解释深度沿用[知识模块](../../../workflow/modules/knowledge.md)的实现契约与图像规范；
本表将它们变为可评价目标，不复制另一份算法或绘图协议。

## 分档、计分与达标

分数使用 0–5 的整数，逐项按实际证据评价，取所有适用检查点能共同支持的档位。
高分需要覆盖和证据，不能因行文流畅或主观“感觉够详细”给分。

| 分数 | 统一含义 |
| --- | --- |
| 0 | 内容缺失或有决定正确性的错误，不能据此理解/实现。 |
| 1 | 只有结论、名称、框图或引用，缺少机制解释。 |
| 2 | 有部分解释，但重要关系、步骤、字段或条件需要读者自行补齐。 |
| 3 | 主线基本可理解，但仍有实质的解释/例子/边界/呈现缺口，需要回源码或会话猜测。 |
| 4 | 本项适用要求完整、准确且可定位，通过相应走查；可独立理解/实施，剩余仅为不影响闭环的小改进。 |
| 5 | 在 4 分基础上，关键难点均被明确的因果、具体例子/反例和必要图文化解，经独立走查无隐含关键前提；组织便于学习、检索和机器抽取。 |

默认目标是各适用项尽可能达到 5 分。允许报告“达到个人标准”必须同时满足：

1. 每个适用指标至少 4 分；四个有适用指标的维度各至少 90/100；总分至少 95/100。
2. 所有要求的检查有证据，已关闭影响正确性或理解/实施闭环的缺口；未关闭的小改进写清处置。
3. 独立 Review 通过。作者自评分只用于修稿，不能替代已有独立 Review；未独立评价时写自查结果。

单页/预先明确的评价单元按以下方法计算，保留原始分数和分母，判定用未四舍五入的值：

```text
总分 = 100 × Σ(适用指标权重 × 指标分数 / 5) / Σ(适用指标权重)
维度分 = 同一公式，仅取该维度内的适用指标
评价覆盖 = 已评分适用项数 / 全部适用项数
适用权重覆盖 = 适用权重 / 原始权重100（同时列出各维度分母）
```

“不适用”须在规划中按文章角色和实际内容逐项说明，Reviewer 核对后才从分母排除；
已有合格图是复用并评价，不是“不适用”。缺来源、没时间、工具不可用、尚未补图或未渲染
都不是不适用理由。无法核验记 `unverified`，适用但内容未写记缺口并给相应低分；
`unverified` 项的分数为 `null`，保留适用权重，此时维度/总分为 `null`，不得报达标。
没有适用项的维度标 `not-applicable`，不得写满分；整张表无适用项时不计算总分。
不得在看到低分后删除适用项、降低阈值或缩小承诺范围；正当的角色/范围调整要记录原因并复核。

不同文章类型或不同适用项集合的总分不直接排名；跨页评价保留逐页结果，所有页面分别达标
才报告整个范围达标。只检查样页必须披露范围，不能外推为全库通过。

下列问题不能被平均分抵消：核心事实错误、图文互相误导、关键字段/分支/同步语义缺失、
不可追踪的关键证据、虚称运行验证，以及 Agent 走查依赖未写出的决定性步骤。
按既有 blocking/provisional/minor 规则修候选或记录待补证；分数只提供可解释的质量判断，
不替代来源、权限、独立 Review、恢复与 CAS 门禁，也不新增一套 MCP 字段或审批流程。
现有协议若允许带缺口发布，应明确仍未达到个人标准，不能把“发布成功”说成“质量达标”。

## 写作与审查怎样使用

1. **规划**：确定页面/专题、文章类型、读者与同版本关联契约，逐项确定适用性；将指标 ID、
   拟落章节/锚点、必要图/图注、来源与缺口写入已有计划/PageJob。全文讲解目标优先于压缩篇幅。
2. **写作**：按概念→因果→具体例子→实现细节→边界/验收展开，按需调整顺序。维护正文、
   图与图注的一致性；对照每项自查并修订，不为了凑表格、字数或图数重复内容。
3. **独立评价**：复用当前 Reviewer 和绑定候选，先进行下述走查，再逐项给分/证据/缺口；
   先检查仅凭候选能否理解/实施，再核对来源，避免 Reviewer 用源码知识补齐缺失正文。
4. **修订与交付**：先修事实和闭环缺口，再改难懂章节与图注，最后完善导航和呈现；
   仅复核变更影响项和未关闭问题，重算受影响分数。记录达标情况与未验证项，复用既有发布流程。

每次实质技术更新的 Review 至少包含三类文本走查，覆盖本次修改的全部关键机制；
可以用一条贯穿例子串联，复杂专题增加用例，不能只选最容易的片段：

- **人类理解**：仅依据候选及显式先备链接，复述问题、概念、因果、设计取舍与一个边界/反例；
  把无法从正文回答的问题列为具体缺口，不能用 Reviewer 的背景知识代答。
- **图与图注**：逐张说明本次新增/改动图回答什么问题，解释一个具体对象/字段/区域的变化，
  核对它与正文及来源的对应关系；按实际阅读宽度另做视觉检查，记录全部/抽样及未检查范围。
- **Agent 实施**：仅依据正文和显式实现契约，从输入、环境条件、数据布局走到关键步骤、
  中间产物、消费端与验收结果；至少包含一条正常路径和适用的失败/边界路径。
  对每个无法确定的参数、分支、依赖或验收出口，列出应补充的章节和影响。

文本走查、图文核对和实际设备/运行验证分别记录。未运行不自动降低清晰度评分；
正文如实说明未运行，且实施/验收方案有足够来源与细节时，仍可达到文本质量目标。
需要运行证据才能成立的事实另按证据缺口处理，不能靠高文本分变成已证实事实。
评价不额外授权编译、清缓存、高成本实验、业务代码修改或扩大来源许可。

## 评价记录与机器可理解性

在已有任务/审查记录内保留评价，不把评分流水塞进 Wiki 正文开篇，也不另建强制后端状态。
最少记录：本标准的标识及绑定 revision/hash、候选页面/包的版本身份、评价者与覆盖范围、
各项适用性/分数/正文位置/检查方法/观察结果/缺口与修订动作、维度和总分、三类走查及
实际视觉/运行状态。跨页契约也须绑定版本，变动后受影响项失效，不能复用旧分数。

下面是结构示意，非已执行评价；真实记录展开全部十二项，不能只交付一个综合分。
`applicability` 使用 `applicable` 或 `not-applicable`；适用但未核验的项仍为 `applicable`，
`checkStatus` 为 `unverified`，`score` 为 `null`。已检查使用 `checked`；不适用使用
`not-applicable`、`score: null` 并填写具体理由。`decision` 为 `pass`、`revise` 或 `unverified`，
这些只是本次质量记录，不是 MCP 发布状态。

一条证据应包含稳定的页面/图注锚点、检查方法、可复述的观察结果和限制；技术事实另给

Markdown/JSON/SVG 解析成功、关键词命中或模型自报置信度代替。
