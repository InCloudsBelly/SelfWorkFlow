# 审查与复核

普通 agent-policy 的审查指导，不因模式名称、阶段或文件类型自动创建 Reviewer、前置审批或第二轮审查。用户明确要求独立审查，或明确采用 [Full](../modes/full.md)/[Deep](../modes/deep.md) 等严格方式时，履行相应保证；显式契约仍按[契约门禁](../legacy-host.md)。

## 选择与范围

依据误判后果、可回退性、可验证性和现有证据，选择自审、独立复核或其他必要核验。仅要求代码审查时，可由主 Agent 直接完成，不必另设一个审查者审查其报告。项目审查配置指定的检查内容须遵守；配置存在本身不额外推导独立角色或契约门禁。

按请求固定比较范围、基线和真实需求；未提交审查包含相关暂存、未暂存及未跟踪增量。沿实际受影响路径查正确性、兼容性、安全与验证缺口；正常、失败、边界、生命周期等作为查漏思路，不为无依据的假设扩大支持范围。行为代码需要专业检查时参考[代码审查方法](../../methods/code-quality/references/review-rules.md)，不因引用预载。

成立的发现给出可达触发、位置、后果与依据，区分确定缺陷、条件风险和待补证据。只要求审查时报告发现，不擅自扩为修复任务；实施交付不能掩盖仍影响验收的重要问题。完成表示约定范围已审或有据不适用，不表示穷尽缺陷；范围未完成或运行未验证须说明。

## 复用与协作

已有结论仅在输入、规则、环境和消费者依赖仍适用时复用，包含未提交增量；不能只凭 HEAD、字节或 dirty 状态判断。按变化和影响补查，无法确认旧覆盖时重核必要范围；用户明确要求重新或完整审查时按其范围执行。

复审通常聚焦未关闭问题及其影响，保留上次结论和必要证据入口，不要求固定状态表、ID 或逐行清单。没有新依据的重复审查不代替补证；也不因次数或预算跳过用户要求的覆盖。

委派有实际收益时再使用。给出足够的目标、候选和证据，优先最小上下文交接；是否复用原 Reviewer 按问题连续性和独立视角的价值判断，不机械轮换。协作不扩大权限；只读委派遵守允许动作，不自行修复或运行未获授权的验证。声称独立须有真实独立上下文，不能只换角色名；缺能力或证据如实报告，必要门禁不能伪造或自行豁免。

回传以发现、证据、已审范围和剩余缺口为主，深度与格式按请求决定，不重复有效旧材料。普通 agent-policy 不强制工作流契约的 package/receipt/runner 或清理回执；业务任务所需产物与核验不因此免除。
