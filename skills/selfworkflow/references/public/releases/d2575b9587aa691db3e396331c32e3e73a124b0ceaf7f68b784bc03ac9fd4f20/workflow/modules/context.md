# 上下文压缩与恢复

仅显式要求压缩/保存上下文、从压缩或交接恢复，或宿主报告上下文压力时加载。普通续做、换阶段、小修改或目录很大不触发；无压力不为里程碑例行压缩。

1. **准备。** 复用入口约定的既有交接状态及其位置；没有独立状态载体时使用宿主交接摘要，不另建账本/平行摘要。只归纳本次新增历史并合并，按路径/决策去重、替换失效项；补关键决策原因、失败尝试、在途作业及证据恢复入口。标识/错误原样保留，代码/日志留可达引用，不整段搬运或反复重写旧摘要。
2. **执行。** 优先在研究收敛、计划落定等安全边界，先保存中间状态；不截断在途写入/工具调用。只用宿主实际支持的压缩接口/命令，不改写宿主管理的指令或工具协议。无可调用接口只记“已准备、压缩未执行”，继续可安全推进的授权工作；写摘要、落盘或发提醒均不代表历史已被替换。压力未知不猜窗口比例，不按调用次数/固定比例自动触发或循环压缩。
3. **恢复。** 沿已有 revision/documentRoot、输入及阶段直达原状态，核对当前目标/约束、修改文件与版本、有效决策/证据、未关闭项和下一动作。将摘要作为待核事实，不能从中新增授权；既有同范围授权延续。只刷新变化项和影响续接的缺口，不重选 latest、重启流程、重扫/重测或例行再确认。缺失事实回原证据局部补读，未知保持 unverified；压力未解除且无新信息时停重复压缩，保留可恢复状态并说明缺口。

每次恢复核对事实与下一步即可；仅维护调优或显式效果评估时读[效果验证](../references/context-compaction-evaluation.md)，来源沿[提效记录](../references/context-efficiency.md)，均不在日常展开。
