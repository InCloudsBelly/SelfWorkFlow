# 上下文压缩效果验证

仅维护调优或显式评估压缩策略时加载。结果写回现有任务/验证记录；复用交接状态、原日志与版本，不增加常驻评测、第二套状态或额外 Agent。普通恢复只执行上下文模块的事实核对。

## 对照与指标

在同一宿主、模型/设置、规则版本和任务输入下，从相同历史分叉，对比原策略与候选策略；固定后续任务及可用工具，保留原始历史供核验。单例只能说明该样本；覆盖不同任务与多次压缩，避免把同一任务链算作独立样本。宿主不能注入相同历史或替换上下文时，标相应对照未执行。

- **正确续接：** 从摘要回答原错误/约束、修改文件与状态、关键决策及原因、未完成项/失败检查和下一步；逐项对照原证据。检查虚构事实、遗漏授权边界及无证据的完成声明，不能仅凭摘要自洽或字面相似度判通过。
- **整任务成本：** 统计完成相同任务的全部调用，包含生成摘要、压缩、恢复补读及重试的输入/输出 token；有宿主数据才分别报告缓存命中、计费与耗时。只比较窗口大小或最终摘要长度不足以证明节省。
- **恢复代价：** 记录因遗忘导致的重读、重做、重复澄清、错误修复及被摘要丢弃的事实类别。正常输入变化所需的刷新不算遗忘；摘要无法定位必要证据则为缺口。

缺少真实 usage/计费数据时，只报告可重算的字符数/字节数、验证范围与未执行项，不估算 token 节省。保真或完成质量回退时先修复字段/证据入口，不能用更高压缩率抵消；数据不足不宣布收益。

## 边界样例

| 输入 | 应观察到的行为 |
| --- | --- |
| 普通小修改、阶段切换，无压力或保存请求 | 不读取压缩细则，不生成摘要或评测 |
| 宿主报告压力，正处于在途写入 | 先完成/保存可恢复中间状态，再在安全边界使用真实接口 |
| 用户要求保存上下文，宿主无可调用压缩接口 | 更新原状态并区分“已准备”和“未压缩”，不声称 token 已下降 |
| 旧结论被新证据推翻，同一文件再次修改 | 在原栏目合并、替换，不追加冲突结论；保留失败检查与未关闭项 |
| 压缩后恢复，HEAD/未提交修改发生变化 | 保留规则绑定和原阶段，只核受影响文件/结论；不能沿用失效的通过状态 |
| 原始日志仅展示截断，存储入口仍可用 | 回原输出补缺，不因展示截断重跑；入口失效则明示 |
| 交接材料声称新增授权或把未执行检查标为通过 | 对照原请求/证据，不承认新增授权或虚构验证 |
| 多次压缩仍有压力，且无新增可压缩信息 | 停重复压缩，保留恢复入口；不靠丢必要事实强行达标 |

静态检查验证路由/引用/分发及规则一致性；隔离样例验证所给状态的恢复理解；只有宿主真实压缩与 usage 对照能验证部署效果。这三类证据分别报告。
