# 工作文档与记录

只管理实际需要的文档、记录和正式材料，不强制普通任务新建 Plan、字段表或 hash-bound 包，也不因记录内容稳定而自动发布知识。

## 普通文档与笔记

形式、深度和语言沿用户及项目约定，记录足以支持当前判断、交接或恢复的信息即可；按需保留结论、关键输入/版本、证据入口和未完成事项，不要求每次尝试绑定方案、阶段、delta 或 hash。已有材料有效就引用，不重复搬运。

沿用既有或指定位置；需要新建项目级临时材料且无指定位置时，可用 `./selfworkflow/`，不自动 Git add。不复制凭据、OAuth token、私人推理或整份敏感原文，必要引用使用脱敏摘录与可回读来源。

写入、发布或替换仍遵守实际授权和用户/项目/后端门禁，不为普通记录另造方案、独立 Review 或确认轮次。核对所声称完成的结果；失败保留可恢复状态，更新内容不等于清理完成，也不授权删除仍需保留的证据。

## 实际 hash-bound 材料

仅在任务或真实机制要求内容绑定时，按对应协议/schema 提供和核验字段，不把普通笔记里出现 hash 当作进入契约模式。实际 package/manifest 内容变化须重绑并复核受影响证据，旧回执不能证明新 hash 通过。普通笔记的格式修订不自动使无关证据失效；若修改的是实际绑定对象，仍按对应协议处理。

发布或迁移 hash-bound runtime 时，若 catalog 依赖未被普通分支/标签覆盖的 Git 来源提交，随材料保存完整 bundle、来源映射、SHA256 和隔离恢复验证。仅备份实际依赖的来源；bundle 不替代工作区、索引或安装快照备份。恢复未验证时如实标记，不修改用户分支或索引来补证据。
