# 代码审查方法

只补行为代码审查的适用检查；范围、调度与收束沿既有 Review，不启动 TDD、构建或写入。普通解释分析不加载本页，已读同版复用。

- 场景与反证：从用户约定、项目契约及真实调用确定已支持场景，提出缺陷假设并沿基线和消费者证伪；不临时补限制排除问题，也不把明确排除的重跑或假想未来场景报成缺陷。
- 生命周期：跨被调函数追踪创建、持有、异步等待、发布和释放，检查中途回收/回调及失败退出；对象标记或外层归属不自动等于保活。
- 资源与全局状态：结合空间范围、数量和持有时间评估常驻成本，区分必要输入与临时资源；恢复须核对有效语义，适用时包括优先级/标签/历史，不能只恢复表面数值或标志。
- 紧凑性与侵入：对比等价删除/内联冗余状态、薄包装、重复遍历及局部替代，区分代码净减少与仅搬移；按影响半径判断，不以少几行换取共享行为扩大，不删必要恢复、保活、兼容或调试能力；审查建议不自动授权重构。
