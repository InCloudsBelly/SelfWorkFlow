# Wiki 设计边界逆向质询

技术前提、反事实或跨单元耦合难判断时读取；基本要求已在[主标准](wiki-quality.md)。复用范围清单、来源、章节与同一Reviewer，不另开访谈或问卷，不要求所有Wiki固定八字段FAQ。

1. 从候选/显式同版契约找出无法回答的目的、前提、不变量或边界，给能区分答案的条件/反例；已有答案直接引用。已看源码如实披露，不为模拟盲测先造初稿。
2. 核对绑定版本的入口/准入、判断、生产消费、状态更新及退出/回退，覆盖实际必要条件及交互。结论区分来源支持、反驳、仅所列条件支持、未核实；范围不足不声称行为不存在。
3. 新发现回补范围和正文、公式、图注、共享契约；被反例推翻时回查前提，不只追加FAQ留下矛盾。Reviewer先据候选自选问题/反例，再核来源与遗漏；全部关键单元须有覆盖，可共用贯穿案例，修订只查影响项。

按实际机制选择有判别力的问题：

| 要点 | 检查 |
| --- | --- |
| 目的/选择 | 什么约束导致设计，替代何时不同，理由是记录意图还是推断。 |
| 前提/边界 | 范围、单位、布局、容量、有效状态由谁保证；违反后报错、截断、回退或未知。 |
| 条件/时序 | 编译支持、运行准入、有效配置/优先级、提前返回；创建、同步、失效/释放和并发/跨帧配对。 |
| 变化/验收 | 改位宽、精度、容量、坐标、顺序或平台会破坏什么；哪些两端/资产/缓存须联动，如何观察正常、失败、边界及恢复。 |

正文给可定位的问题/直接答案、因果、条件、例子/反例、来源及必要联动/验收；章节锚点可充当稳定问题ID，不重复抄字段。来源事实、明确记录意图、带假设/可反驳条件的解释性推断、未知/冲突分别说明。代码做法不证明作者动机，常量不证明硬件/算法极限；原始动机未知但行为/边界已核验不自动扣分，关键行为未知仍是缺口。

例如4位编码有16种值，若生产端拒绝`>=0xF`、消费端以`0xF`判空，应区分编码数与有效索引数，再核实际容量约束；用`0xE`、`0xF`和越界输入检验，不能据此编造ABI设计动机。这是方法示例，不是项目事实。

初始问题、来源后发现和暴露情况在已有记录简述，只保存面向读者的论证/证据，不保存私人推理或草稿链。超主题问题留待研究，不无限追问；不授权实验、业务代码变更或发布。
