# 按需实施与交付

只读当前命中的一项；不因 Full/Deep、代码完成或出现 PR 链接预载。沿既有绑定、授权和证据，不重开流程。

已有领域分工直接复用，不叠加编排。仓库实施的同一有效方案只判一次：目标/验收清楚，至少两个独立验收、低写冲突的工作包，预计并行/上下文隔离收益值得协调成本，才选 implement-spec；否则常规实施。不因文件多触发，不派判别 Agent、不建评分表。范围/依赖/能力实质变化才重核；用户明确要求选用时直接核前置条件。

| 意图 | 入口 | 边界 |
| --- | --- | --- |
| 薄判别选用，或明确要求用 `implement-spec` 实施 | [implement-spec](../../methods/implement-spec/METHOD.md) | 复用紧凑计划，必要时最小拆票；派发前核规格、至少两票 DAG、计划审查及授权。小任务、单票、高耦合或仅规划/审查不自动触发。 |
| 撰写、更新 PR 正文，或已请求创建 PR | [pr](../../methods/matt-pocock/pr/METHOD.md) | 复用实际 diff、验证与风险；PR 代码审查仍归 review，不自动发布。 |
| 明确要求对当前/指定会话 retro、复盘效率或 token 浪费 | [retro](../../methods/matt-pocock/retro/METHOD.md) | 基于指定历史一次汇总；不在每票、每次修复或交付后自动运行。 |

只复用相关输入、规则及环境/消费者依赖仍有效的证据，不因阶段切换重载默认 implement 协调、审查或测试；变化只补影响项。PR 请求授权范围内的动作沿用，不从方法引用推导 push、merge、关闭任务或修改其他会话。
