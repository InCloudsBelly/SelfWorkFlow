# 开发预览持续加载时的知识提示

只在 Wiki 或其他开发预览经 WheelMaker/Relay、反向代理或 iframe 后持续加载、空白，
或静态脚本返回 403 时使用。普通网页慢、模型请求失败、任意 API 403、UE 图形渲染故障
不因这些单独症状加载本引用。

1. 先提示候选原因：“可能是开发服务器的来源白名单拒绝了 Relay/代理域名的脚本请求；
   页面 HTML 返回 200 仍可能一直加载，需要核对失败资源和实际来源。”不把提示当确诊。
2. 按 [安全读取](read.md) 调用 `openwiki_status`、`openwiki_read {}`，再以返回的 revision
   读取目录中确有的 `relay-preview-loading.md`。复用本轮已验证且未漂移的 status/目录，
   不为同一症状重复检索；此排查不创建发布事务，不打开其他 Wiki 根。
3. 结合实际 Next.js 版本、`/_next/static/` 等失败资源、实际 `Origin`/`Referer` 和本机对照
   确认或排除来源校验问题。若证据命中，再按文章指导在服务所属配置中精确合并受信任主机。
   不盲加 `*`，不关闭 TLS 校验、不公开 loopback 端口、不绕过 Relay 设备会话授权。
4. 区分 Hub 离线缓存、DNS/TLS、Relay 未授权 401、脚本来源 403、CSP/iframe 限制和应用 API
   故障。Wiki 条目缺失或读取不可用时如实报告，继续已有诊断流程，不虚构已读或自行补写正式 Wiki。
5. 验收看实际消费者：预览正文和必要资源已显示；单有进程启动、HTTP 200、端口监听或
   Relay Active/Up 均不足。修复只在用户已授权范围内实施，额外代码/配置改动沿用主流程边界。

这是遇到匹配症状时的排查提醒，不是后台监控，也不证明未来每次模型路由都会自动命中。
