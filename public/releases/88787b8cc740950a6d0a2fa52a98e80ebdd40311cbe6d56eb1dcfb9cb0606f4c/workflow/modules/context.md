# 上下文保存、压缩与恢复

需要相关操作指导时参考。普通续做、换阶段、代码库规模、响应慢、C++ 内存问题或纹理压缩不表示上下文压力；引用中的措辞也不构成当前操作请求。

目标是保留可继续工作的真实状态，不要求固定枚举、三套状态表或额外账本。复用已有位置，保留必要的目标/授权、规则绑定、输入与环境、有效决策/证据、失败尝试、在途作业、未完成项和下一动作；代码/日志保留可达入口，替换失效结论。

保存摘要、实际压缩和恢复核对是不同事实：写出摘要不表示历史已替换，压缩成功也不表示所有事实已恢复。只有实际存在且获授权的宿主接口可执行压缩；用户仅要求保存时不自行升级为压缩。无接口、未返回或失败如实说明，不伪造宿主状态、提示或压缩结果，也不改写宿主管理的指令/协议。

恢复时沿原目标、授权、revision/documentRoot 和未完成责任，核对必要输入、修改、环境及消费者状态；摘要是待核事实，不新增授权。有效内容直接复用，变化或新证据按影响补查；有效性不能确认时重核必要范围，不因恢复重启流程、重选 latest 或重复询问已覆盖权限。

在途写入或工具作业先保留可恢复状态，再于安全边界使用实际能力；保留中断和必要进度。无新进展时不反复请求压缩或重启作业。当前对话摘要没有跨会话载体时，说明持久性未验证。

只有评估策略效果时再参考[效果验证](../references/context-compaction-evaluation.md)与[来源](../references/context-efficiency.md)；摘要更短、窗口下降或恢复自洽均不能单独证明成本或保真收益。
