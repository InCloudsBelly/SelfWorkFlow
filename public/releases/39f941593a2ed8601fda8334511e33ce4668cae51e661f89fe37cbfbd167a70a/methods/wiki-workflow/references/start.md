# 使用与依赖

将完整 `wiki-workflow` 目录交给支持 `SKILL.md` 的宿主；可从维护仓库 clone 后复制该目录到宿主的 Skill 目录，或直接使用仓库中的入口。保留 `references` 和 `extensions`，不要只复制入口。该包只有流程规范与引用资料，无需生成器、npm、Python 虚拟环境或 submodule。

首次可请求：“基于这些资料整理某功能的原理、实现和细节 Wiki，先交付完整候选。”默认沿用完整技术 Wiki 质量标准。需要指南时可请求：“保留现有原理文，另补一套能查不生效问题的操作指南。”也可明确要求双套。DocHub 默认交付使用／排障稿；需要原理全文时明确指定，已绑定用途的稿件修复沿用原用途。目标和来源已明确时直接执行，不追加固定问卷。

后续可请求：“把这次操作问题和检查结果补进对应指南，原因未明先记录待验证，定位后再补处置及验证结果。”维护按当前反馈、排障或版本变更任务触发，沿用已有范围与授权。

先核实宿主能读取授权来源、保存候选以及预览交付格式。缺少源码、网页权限或渲染器时，记录受影响结论，继续独立工作。未选发布目标时在显式选择的目录生成 Markdown 和必要媒体，不探测发布服务。读取既有知识库或写入服务时才核相应适配能力。

SelfOpenWiki、代码图谱、符号计算、浏览器和各导出服务是按需能力，不随 Skill 自动安装。只用实际可用且获授权的工具；代码图谱已选用时查相关关系，未选用时用真实源码和已有导航，不假定任何人的数据库、账号或工程路径。

适配器指导 Agent 使用当前环境中真实可用的解析、渲染、浏览和发布工具，不把工具代码或维护者的运行环境当作 Skill 的固有能力。MCP、服务登录和目标归属由使用者核实，不携带维护者的凭据、文章映射或 Wiki 数据。
