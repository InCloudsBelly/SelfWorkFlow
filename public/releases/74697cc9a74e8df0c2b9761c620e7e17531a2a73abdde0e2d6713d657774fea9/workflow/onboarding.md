# 新 Agent 快速接入

首次接入或更换宿主时读本页；已经接通的宿主直接按 [工作流主规则](../WORKFLOW.md) 处理原任务。本页只负责接入，阶段、授权、测试和 Review 仍由主规则及其模块管理。

## 给新 Agent 的一句话

把下列内容中的入口地址和原任务替换后发送给 Agent：

```text
请实际读取并遵循 <SelfWorkflow 固定入口地址>，按其中的首次接入指引核对当前宿主能力，然后继续完成：<原任务>。仅在必要信息缺失时提问，不把接入变成一次环境安装。
```

固定入口是公共目录最外层的 `WORKFLOW.md`，可以是本机文件、共享文件地址或可读取的静态 URL。远程宿主必须使用它实际能读取的地址；维护者本机的盘符不会自动对其他机器可见。离线交付须包含固定入口及其引用的完整版本目录；只导入一次内容的宿主需要在更新时重新分发。

## Agent 按顺序做什么

以下是完整接入顺序；已经完成的读取直接复用。已有或收到主任务的 `revision` 与 `documentRoot` 绑定时，从该版本继续，不重新选择固定入口版本。

1. **尚未绑定时实际读取入口。** 跟随“读取本任务规则”链接，读取目标版本的 `WORKFLOW.md` 和它要求的文档使用约定。固定入口不可读时，只报告地址或读取能力缺口，请求一个可读取的位置，不猜测旧安装目录。
2. **记住本任务版本。** 从入口取得 `revision`，目标版本 `WORKFLOW.md` 的父目录为 `documentRoot`。文件路径和 URL 都保留各自的地址形式；相对链接从声明它的文件解析。后续阶段、续接和独立 Reviewer 使用同一绑定，不重新选择 latest。
3. **核对本任务需要的能力。** 使用当前会话实际提供的工具协议与权限填写下表；有宿主说明时将其视为线索，仍核对当前事实。没有执行过的连接、命令或完成回执不能记为已验证。不要为接入而探测全部服务或执行环境安装。
4. **选择模式并继续原任务。** 按主规则根据原任务的复杂度与风险选择模式，只读该模式、当前阶段模块和 `methods/INDEX.md` 中命中的方法。缺失必要能力时报告受影响的步骤和下一步，继续独立且获授权的工作；不得为绕过门槛降低模式。
5. **仅在需要跨会话复用时保存接线。** 采用下方模板，由宿主的持久指令加载；已有固定入口时无需再创建文件。不能持久加载的宿主可先在本次会话使用，后续新会话重新提供入口。

| 能力 | 什么时候需要 | 核对什么 |
| --- | --- | --- |
| 文档读取 | 所有接入 | 能读取固定入口、目标版本和按需引用；能正确解析文件路径或 URL |
| 项目读取、写入与命令执行 | 原任务实际需要时 | 明确的项目根、当前工具参数、权限及执行结果；能读文档不代表能修改项目 |
| 独立上下文与完成信号 | Full/Deep 的独立 Review | 创建方式、隔离语义、传入任务版本、等待和实际完成结果；见 [Review 模块](modules/review.md) |
| CodeGraph | 代码任务命中结构化读取或写后维护时 | 实际连接、项目绑定及新鲜度；见 [读取模块](modules/codegraph-read.md) 和 [更新与完成门槛](modules/codegraph-update.md) |
| Wiki 等专业服务 | 原任务命中相应操作时 | 当前连接、授权与所需操作能力；未使用的服务不成为启动条件 |

工具名称、厂商名称和配置声明都不是能力证据。普通文档接入不需要 SelfWorkflow CLI、Python/Node、原生 Skill 注册或旧 Adapter YAML；真正需要的工具部署单独处理。

## 可选的轻量 Adapter

使用 [宿主说明模板](templates/AGENT_ADAPTER.md)。它是一份由宿主拥有的短 Markdown，只保存固定入口、项目位置来源和实际工具信息，不复制工作流正文、方法触发条件或阶段规则，也不固定某个发布版本。

宿主已经支持全局或项目级持久指令时，将填好的说明放在该宿主**明确支持且获授权的位置**，或让其持久指令明确加载该文件。仅创建一个 `HOST.md` 不代表宿主会自动读取；当前 Agent 不知道加载机制时，只给出说明文本和这个缺口，不猜配置路径或改写其他工具配置。保存配置仍遵循主规则的授权边界。

此模板走普通文档入口，不依赖旧 `adapters/<id>/adapter.yaml` 或组合程序；文档模式的受管入口也不会自动加载旧 `adapter_text`。工作流更新后接线保持不变；仅文档地址、宿主工具或持久指令加载机制变化时更新宿主说明。

## 接入完成的最短核对

首次接入时简短报告以下事实，然后继续原任务，不要求用户再确认一次已经授权的工作：

```text
文档绑定：<实际读到的 revision 和 documentRoot>
本任务能力：<可用能力及尚未验证的部分>
必要缺口：<影响的具体步骤，或无>
接下来：<原任务的下一步>
```

创建独立 Reviewer 时，在主流程规定的委派材料中显式附上当前 `revision` 与 `documentRoot`，让其读取同版必要规则；不要假定全新独立上下文已经继承这两个值。完成时核对真实结果，而不是把“已发送任务”当作“已完成”。

入口可读只证明文档接通，不代表 Full/Deep、工具连接或原任务已经通过。跨宿主冷启动与模型遵循效果需要在实际宿主验证；这份指引本身不提供这些执行证据。
