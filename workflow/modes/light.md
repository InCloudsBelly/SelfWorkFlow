# Light 模式

适用：低复杂度、低风险、范围清楚的只读或小修改任务。

- 只读任务仍先读取启动入口和本模式文件，再读取命中的能力模块；`writeTask=false`，不编辑、不产生副作用；纯分析不自动 Grill 或 TEA。
- 修改任务做紧凑 Design/Plan、代码实施契约（如适用）、窄 Review 和最小充分验证。
- Light 的窄 Review 可由当前 Agent 结构化自审或交叉检查完成，必须如实标记并不冒充独立 SubAgent Review。
- 行为变更仍必须 TDD；至少覆盖直接路径、失败路径和最窄相关回归。
- 发现计划外问题只记录并完成当前目标；阻塞验收时停止并回到 Plan。
- 完整 grilling 和 TEA 仅用户显式点名加载，不因模式或测试等级自动触发；重要未决选择仍需确认。机械文档同步不单开 Reviewer，不因 Token/次数预算中止未完成任务。
