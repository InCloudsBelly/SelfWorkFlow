# 编译缓存保护

- 新编译模块/公共接口首个最小可加载切片后取得最窄构建反馈，再叠加依赖它的功能；禁自动执行则集中给人工步骤、输入指纹、日志与预期，等待期间继续独立工作。用户已接受未验证续做时沿用授权；静审不代替编译/加载证据。

- 执行前核对最近正常构建的命令、日志或配置，保持项目、构建目标、平台/架构、配置、工具链/SDK、全局参数和缓存设置一致。在同环境下优先做最窄充分的增量验证。无法确认环境时先报告，暂缓试编。
- 只有当前验证涉及 UE 构建链时才读 [UE 构建缓存](build-unreal.md)。
- 未获明确授权，不执行 Clean/Rebuild，不删除或清空产物/缓存，不通过切换全局构建选项或改写构建规则绕过编译检查。
- 共享头、构建规则或工具链等必要变化仍可能合法触发大范围重编；预计有此影响时，先说明原因、范围和代价并取得用户确认。不同编译环境的验证使用已确认不会覆盖原产物/缓存的隔离输出；不能保证隔离时不执行，保留 `not-run/unverified`，不得把跳过说成通过。
- 实际动作量显著超出改动影响范围时，检查构建计划、全局设置和共享缓存的失效原因，不反复切换参数重试。安全可行时只暂停本 Agent 发起的构建并报告。
