# 工作文档与留痕模块

- 设计、TEA 测试设计、实施计划和 Review 摘要是过程证据；正式文档必须中文、可追溯到请求和验收条件。
- 项目级临时工作文档、决策记录、Review 结果和待办放 `./selfworkflow/`，不自动 Git add；真正稳定知识按知识模块另行沉淀。
- 每次新尝试绑定请求、Plan、阶段、完整 delta 和 hash。请求、范围、设计、计划、验收或验证输入的文档变化，只使依赖这些变化的 Review/验证失效；格式或拼写修订检查受影响文档，未改变输入的代码回归和其他证据可复用。实际 hash-bound package/manifest 变化仍按 Review/契约规则重新绑定和校验，不得把旧回执当成新 hash 的通过证明。已否决、失效或重复的临时记录应在保留审计必要性的前提下及时标记、归并或删除。
- 不复制凭据、OAuth token、私人推理或完整敏感原文；需要引用时保存脱敏摘录、来源标识、hash、结论状态和验证证据。
- 更新采用 `plan → review → confirm → apply → reread`；失败保留可恢复证据，未复读和未验证不得报告成功。
- 发布或迁移 hash-bound runtime 时，若 catalog 依赖未被普通分支/标签覆盖的 Git 来源提交，随材料保存完整 bundle、来源映射、SHA256 和隔离恢复验证。仅备份实际依赖的来源；bundle 不替代工作区、索引或安装快照备份。恢复未验证时如实标记，不修改用户分支或索引来补证据。
