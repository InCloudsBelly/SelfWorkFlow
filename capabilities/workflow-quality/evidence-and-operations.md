# Evidence and operations

Completion requires fresh evidence bound to the current review package, which contains actual specification text, worktree/index bytes and Git modes, task delta, and at least one confirmed verification plan rather than only paths or hashes. Full/Deep uses distinct Standards and Spec Review receipts with the same package hash; Critical/Important must be resolved and Minor findings disposed. Complete rejects caller-supplied Verify receipts and uses the bounded runner to execute every bound plan itself, recording exact command, times, exit code, failure count, output hashes, and structured consumer result. Process cleanup reaps the group leader before confirming the remaining container is empty. Any package drift invalidates Review and verification. Side-effecting batches require a reviewed plan, explicit confirmation, apply result, reread, rollback evidence, and a failure-injection rollback check. Missing capability or evidence remains visible as `unverified` and blocks completion.
