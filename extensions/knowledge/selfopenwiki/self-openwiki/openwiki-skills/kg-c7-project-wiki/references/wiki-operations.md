# OpenWiki 本地知识操作契约

## 页面层次

- `/quickstart.md` 是入口；项目主题位于 `/projects/<project>/`，来源覆盖位于 `/sources/`。
- 不创建嵌套 `/openwiki`，不把宿主绝对路径写成稳定 Wiki 路径。
- `index.md`、`log.md` 和事务 control 是保留内容，不作为普通概念页改写。
- 初始化先盘点入口、已有页、来源覆盖和变化；按稳定主题分组，不按 raw 文件数量建页。
- 新页须通过 Markdown 链接从 `quickstart.md` 可达，可以经由已有主题导航。需要修改的手工导航页也属于页面计划；不要把它们当成保留索引遗漏，或在候选之外补写正式入口。

每个主题页至少回答：是什么、为什么存在、从哪里开始、关键不变量/风险、如何验证、来源是什么。没有来源变化时，不为制造“更新”而改写准确页面。

## 来源与 canonical 知识

- raw source 只读，是线索与证据，不是最终知识层。
- 当前代码/配置/测试优先于旧文档；冲突要同时引用并标记。
- 来源页保存 ID、manifest/hash、覆盖范围、时间和短摘要；主题页保存跨来源仍成立的综合。
- 不自动复制源码或整份文档。必要摘录必须短、脱敏，并说明为何无法仅用锚点表达。

## Session

只有明确要求归档时触发。建议结构：背景、本次沉淀、引用证据、稳定结论、操作流程、验证与风险、后续建议。Session 页保存一次决策过程；项目页保存跨会话仍成立的架构和方法。后续优先更新 canonical 页面，避免重复 session 摘要。

## 质量检查

- front matter 合法，链接目标存在，关系语义明确；孤立页需合并或说明。
- Mermaid 只用于拓扑、生命周期、依赖或跨阶段关系；含标点节点使用引号。
- 检查重复结论、过期 commit/报告、`contested`、`watchlist` 与 open questions。
- 不把未抓取、SSO 失败或空数据误写成“没有记录”。
