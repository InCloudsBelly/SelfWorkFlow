# 工作报告与 Session 知识沉淀

## 来源分流

- 日报/月报/半年报/年报明细来自工作汇报系统；长于一个自然月时按月拆分、按 report ID 去重，并记录原始/去重数量。
- 引擎组周会以 docs 云文档完整正文快照为准，不用工作汇报 weekly 空结果代替；个人总结必须按明确姓名提取。
- 无已登录抓取能力时，只使用已确认 raw connector、导出文件或用户材料，并明确“未抓取”。
- Git 报告按用户时区的 AuthorDate 筛选，使用 commit hash 去重；不要把 CommitDate/cherry-pick 当工作归属时间。

## 去重与沉淀

按“主题 + 动作 + 结果”合并日报、周会和 Git；日报补细节，周会补背景/难点/计划。不要写日期流水账，也不要把同一事项重复列为多个产出。

报告进入 Wiki 时：

1. 提炼稳定架构、方法、工具入口、证据和价值；
2. 更新项目 canonical 主题页；
3. 来源页记录报告 ID/日期/覆盖与 hash；
4. 临时进度、绩效措辞和个人敏感信息不升级为技术事实。

AI 增量只写真实资产和提效证据，例如规则、Skill、Agent 流程、日志分析、Code Review、ToolBox/Jenkins；说明减少了什么重复劳动。

## Session 分工

Session 页保存一次会话的背景、决策、步骤、证据、验证和风险；主题页保存跨会话仍成立的结论。只有明确要求归档时创建 Session；不保存 transcript、secret、临时日志或机器本地路径。后续会话更新 canonical 页面，不持续制造同义 Session。
